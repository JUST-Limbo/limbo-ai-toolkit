# 从报告到源码优化

## 先建立证据

按 `stages` 判断数据完整性。定位最大包和大文件，读取其模块上下游，再到源码搜索对应页面、组件、资源引用。uni-app 产物中的 `common/vendor.js` 可能合并了多个 npm 依赖；仅有文件体积不能推出某个库精确占用多少，缺少构建级 sourcemap 或依赖分析时要明确“不确定”。

优先追溯 `pages.json`、`manifest.json`、`easycom`、入口注册、共享工具模块、Vue 2 的 `vue.config.js` 或 Vue 3 的 `vite.config.*`。配置可能带注释、条件编译或由插件生成，修改有效源文件，不能把条件编译文件强行当标准 JSON 重写。

## 决策表

| 现象 | 核实什么 | 可能的源码调整 | 需要验证 |
|---|---|---|---|
| 大静态资源在主包 | 主包、分包和动态路径是否使用 | 分包独占资源随业务迁入分包；确认无引用后移除冗余 | 所有资源路径、真机显示、总包变化 |
| 主包 JS 仅被分包用 | 官方依赖图、源码 import、是否经共享入口间接引用 | 拆分共享入口、调整模块位置、检查分包优化配置 | 重新编译后真实归属，不能只看目录 |
| 主包有分包独占组件 | easycom、全局注册、页面配置、组件子依赖 | 调整组件位置和映射，清理确实无用的全局注册 | 页面渲染及组件内部依赖 |
| vendor.js 大 | 实际使用 API、主包启动链、编译器版本 | 替换重依赖或缩小导入，按当前编译器规则调整分包 | vendor 与分包总体积、行为一致性 |
| 相同内容资源多份 | 分包独立性、路径语义、缓存和网络约束 | 可共享时复用；必要副本保留 | 主包是否反而变大、离线和首屏行为 |
| 未关联文件 | 动态拼接、文件读取、平台约定、插件引用 | 证据充分时移除源文件或调整打包排除项 | 不能只凭 moduleId:null 删除 |
| 页面适合分包 | 入口、tabBar、导航、分享、预加载及业务频率 | 调整 subPackages 和相关路径 | 路由完整性、冷启动与分包加载 |

只在目标编译器确实支持时应用 `optimization.subPackages` 等配置。支持 Vue 2 和 Vue 3 **分析**不代表它们的 npm 拆包、组件抽取、异步加载策略相同；不要把 Vite 插件或 Vue 3 专属行为移植到 Vue 2 Webpack。涉及编译器特性时核对当前依赖版本与官方说明。

异步分包、独立分包、CDN 迁移、插件安装、业务路由重构等可能改变加载时序或运行约束，先给出具体影响再按用户授权执行。不要为了让报告变小而盲目搬走主包必需依赖，也不要直接改编译产物路径。

## 验证闭环

1. 保存原始报告和当前工作区差异，不覆盖用户未提交的改动。
2. 实施可追溯的一组源码变化，加入 Skill 版本注释；严格 JSON 保持合法。
3. 相同 production 构建与微信设置下重新分析，用 `--baseline` 生成差异。
4. 查看文件哈希、各包大小与总量；配置变化会影响体积，需独立解释。
5. 若用户要求验证最终包体，在两侧均有可比 `preview.subPackageInfo` 后再给出最终节省量；只有本地文件对比时明确这个边界。
6. 执行项目可用的回归检查；需要真机而当前不可用时列明待验页面和交互。
