# 教学产物与一致性规范

## 何时读取

在创建或维护学习路线、教学大纲、练习簿、阶段设计和知识手册时读取。准备向用户出题前，也要执行本文件的“一致性检查”。

## 三类持久化产物

默认只建立三类学习产物；现有项目有其它合理结构时先适配，不强行迁移。

| 产物 | 核心职责 | 应包含 | 不应包含 |
| --- | --- | --- | --- |
| 学习计划 / 教学大纲 | 作为 Agent 的持久化教学指令，决定学什么、如何教、顺序、掌握深度和如何验收 | 阶段目标、细化到概念与 API 的知识和工具单元、先修关系、教学顺序与策略、练习链接、状态、证据、复习安排 | 完整题干、完整答案、面向学习者的长篇知识正文 |
| 练习簿 | 承载大纲配套的完整实践设计 | 题目、知识引用、约束、提示、完整答案、测试、解析 | 重复整份大纲、与大纲无关的临时题 |
| 学习笔记 / 知识手册 | 为学习者提供稳定、完整、可检索的知识正文 | 用途、机制、时序、通用教学案例、易错点、排错、资料来源 | 课程进度、课堂聊天、下一轮安排、成套题目及其答案 |

课堂对话是教学媒介，不是唯一状态存储。练习工程是验证载体，不替代上述文档；文件存在也不代表掌握。

可以用一个文件或目录表达一类产物，例如：

```text
学习目录/
|-- 学习计划.md
|-- 练习簿.md
`-- 知识手册/
    `-- <主题>.md
```

文件名和拆分方式服从现有项目约定，职责边界保持不变。

## 阶段设计必须落盘

开始阶段教学前，必须把阶段设计写入实际文件。至少包括：

- 阶段目标、先修条件和进入下一阶段的门槛
- 是否沿用、扩展或更换练习模型，以及理由
- 全部知识、API、语法、注解、框架行为和工具操作
- 每个知识或工具单元对应的说明/使用文档、具体章节、语言、适用版本和查阅任务
- 每个单元的掌握深度、教学顺序、呈现策略和纠偏重点
- 全部候选练习、提示阶梯、完整答案、验证方法与验收标准，并标记必做、可选、合并或复验
- 阶段综合题、变式题和延迟复验安排
- 面向学习者的本阶段完整知识手册初稿

这些内容不得只留在 Agent 当前上下文。用户对练习时机的选择只改变候选题的启用状态和顺序，不临时生成脱离大纲的题目。后续发现遗漏时，先同步更新教学大纲、练习簿和知识手册，再继续教学或出题。

## 教学大纲的精度

大纲应细化到能检查是否超纲的最小有意义单元，而不是只列“大主题”。为单元分配稳定编号：

- `K-*`：语言、框架和工程知识
- `T-*`：环境、工具、IDE 和操作技能
- `E-*`：练习

编号形式可适配现有项目，但必须稳定且可双向引用。

知识单元至少记录：

```markdown
### K-SPRING-MVC-04：请求体绑定

- 内容：JSON 请求体到 Java 对象的转换
- 具体项：`@RequestBody`、Jackson 反序列化
- 先修：K-JAVA-OBJECT-03、K-HTTP-BODY-01
- 教学时机：新增 JSON 接口之前
- 掌握深度：理解并会用
- 核心：绑定发生在 Controller 方法执行前
- 允许查阅：注解的低频可选属性
- 暂不要求：Jackson 源码和自定义反序列化器
- 配套文档：[请求体说明](<具体官方文档 URL>)（官方中文优先，适用于 <版本>）
- 查阅任务：从文档中找到 `@RequestBody` 处理请求体的说明，并用一句话关联到当前案例
- 对应练习：E-SPRING-MVC-04
- 教学状态：未讲 / 已讲
- 掌握状态：未评估 / 学习中 / 待巩固 / 已掌握
- 掌握证据：<独立程度、提示级别和验证结果>
```

工具单元同样具体到实际操作：

```markdown
### T-MAVEN-02：重新加载依赖

- 具体操作：Maven Reload、查看依赖是否进入项目
- 教学时机：第一次修改 `pom.xml` 时
- 掌握深度：会用
- 是否背快捷键：否
- 配套文档：[依赖重新加载说明](<具体官方文档 URL>)（适用于 <版本>）
- 查阅任务：在文档或 IDE 帮助中找到重新加载入口，并确认完成标志
- 完成标志：依赖不标红，目标类可引用，项目可编译
- 对应练习：E-TOOL-MAVEN-01
```

计划进度、掌握证据和复习日期默认维护在教学大纲中，不另造一份与大纲脱节的状态表。

## 练习簿条目

每道练习必须包含完整答案，并与题目放在同一练习簿体系中：

```markdown
## E-JAVA-LIST-03：条件筛选

### 对应教学大纲

- 教学单元：集合与业务筛选
- 必需知识：K-JAVA-LIST-02、K-JAVA-LIST-03、K-JAVA-IF-01
- 可选知识：无
- 暂不使用：Stream API、Lambda 表达式
- 目标深度：独立应用

### 题目

<完整题目>

### 完成标准

- <功能结果>
- <边界条件>
- <代码约束>

### 验证方法

<命令、测试输入和预期结果>

### 分级提示

1. <定位提示>
2. <概念提示>
3. <伪代码或局部骨架>

### 完整答案

<完整、可运行的所有必要代码和配置>

### 答案验证状态

- 当前状态：未运行验证 / 已静态检查 / 已运行验证
- 适用环境和版本：
- 建议执行命令：
- 预期结果：
- 实际结果（如已运行）：
- 未验证项或限制：

### 答案解析

- 关键步骤与职责
- 使用的知识编号
- 常见错误
- 其它合理实现的判定方式
```

答案可以用 `<details>` 折叠以减少意外看到，但折叠不是访问控制。完整答案不得粘贴到教学对话或知识手册；需要查看时，应告知练习簿文件、练习编号和“完整答案”小节，必要时提供对应文档链接。

## 完整答案要求

- 提供全部必要文件、类、配置、依赖或明确说明沿用项。
- 不用省略号、伪代码或“其余自行实现”替代关键部分。
- 覆盖题目全部功能、边界和约束。
- 只使用题目允许且大纲已经安排教学的知识。
- 阶段开始前不强制实际编译、运行或测试；必须如实记录验证状态、适用环境、建议验证方法和预期结果，未运行时不得写成已验证。
- 存在多种正确实现时，答案只是参考，不要求学习者逐字一致。
- 未来知识可以作为标明的扩展方案，但不能成为当前题目的必要答案或验收偏好。

修改题目、知识范围、文件名、依赖、输入输出、测试或验收标准后，必须同步修改完整答案。若未重新运行，验证状态必须降为 `未运行验证` 或准确的静态检查状态，不能沿用旧的已验证结论。

知识手册中的案例用于解释知识，练习簿中的答案用于完成特定题目。二者代码完全相同时只保留一份权威副本，另一处使用精确链接，不复制维护两份。

## 双向可追溯

大纲与练习簿是同一教学设计的两个视图，关系可以多对多：

- 每道练习的每个必需知识编号都必须在大纲中存在，且安排在练习之前或当前单元内讲解。
- 大纲中目标为 `会用`、`独立应用`、`排错与迁移` 的知识必须有练习验证；简单 API 可以合并进综合题，不要求一项一题。
- 题干、提示、参考答案、测试和验收标准都受同一知识边界约束。
- 大纲中出现名字不等于已经讲过；向用户出题前还要检查其 `教学状态` 为 `已讲`。`掌握状态` 单独记录，不能用“已讲”冒充“已掌握”。
- 练习或答案需要新知识时，先更新大纲、教学顺序和知识手册，再补讲或推迟练习。

向用户出题前检查：

1. 所有必需知识是否有稳定编号并存在于大纲？
2. 是否已经实际讲解到足以完成该题的深度？
3. 题干是否出现未讲过的术语、API、注解、工具或隐式行为？
4. 提示和答案是否偷偷依赖后续知识？
5. 验收强度是否与声明的掌握深度一致？
6. 大纲中的核心知识是否能由本题或其它题验证？
7. 题目和完整答案是否同步，验证状态是否如实记录？

检查失败时，先补文档和教学，或修改、推迟练习；不能用临时口头解释绕过。

## 环境、工具和 IDE 产物要求

安装、构建工具、IDE 操作、调试、代码生成和快速输入都属于大纲知识。第一次真实需要前应登记并教学：

- 解决什么问题，为什么现在需要
- 当前操作系统和工具版本下的完整命令或点击路径
- 完成后观察什么
- 常见失败表现和排查入口
- 是否需要重启终端、IDE 或运行中的项目
- 掌握深度：独立操作、会用、仅需知道入口或允许查阅

重要操作在练习簿中设置操作题并附完整答案；纯快捷键或低频入口可并入真实任务，不强制单独出题或背诵。

知识手册保存稳定操作路径和排错方式；课堂只在当前步骤揭示需要的操作，避免开课时灌输工具大全。
