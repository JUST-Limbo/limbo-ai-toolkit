# 编程教学与阶段推进

## 何时读取

在设计或调整阶段、练习模型、教学单元、讲解顺序、练习时机、掌握深度以及跨会话交接时读取。产物字段和一致性规则见 [curriculum-artifacts.md](curriculum-artifacts.md)。

## 用能力门槛推进

- 阶段以“能独立完成什么”定义，不以第几天或看完多少页定义。
- 预计耗时只用于安排精力，不能代替验收或成为跳过练习的理由。
- 每阶段明确先修条件、最小产出、验收行为、允许查阅项、暂不学习项和失败后的补强路径。
- 利用学习者已有经验减少重复训练，但不能用邻近经验替代新领域的核心能力验证。

## 阶段切换与练习模型

进入新大阶段前，评估：

- 新阶段是否延续相同的业务对象和代码结构？
- 沿用旧模型会降低认知负担，还是只会训练改名复制？
- 新阶段是否需要验证从零搭建、职责迁移或跨领域整合？
- 旧模型是否已经复杂到妨碍聚焦新知识？

连续性强时沿用或扩展原模型；需要迁移验证或从零搭建时更换模型。新模型应复用足够旧知识，又能暴露新阶段真正需要掌握的问题。决定和理由写入教学大纲，不因追求新鲜感随意换案例。

## 以连贯目标组织教学

文档小节不是课堂次数。将共享同一执行链、共同完成一个目标或分开讲反而割裂理解的知识合并成教学单元；在需要预测、动手或消化的关键点再停下等待。

同时避免一次引入多个相互独立的新概念。计划表或预告中出现名称不算教学，手写题所需知识必须已经按目标深度正式讲解。

## 自适应安排案例与讲解

- 抽象、框架隐式或容易空谈的内容：优先展示最小可运行案例，再沿执行过程解释。
- 有安全风险、重要前置规则或容易形成错误直觉的内容：先讲必要约束，再给整体案例。
- 多组件协作：可先展示完整闭环建立全局图，再按职责拆解。
- 学习者已有相邻经验：从案例差异或迁移问题切入。

不论顺序如何，结束时都应具备完整可对照案例、关键职责、执行时序、失败表现和验证方法。

## 培养查文档习惯

文档查阅是教学步骤，不是课后附录。讲解当前连贯单元时：

1. 提供少量与当前版本直接对应的说明或使用文档，优先官方中文文档；中文官方资料缺失或滞后时使用官方原文。
2. 展示如何通过文档目录、站内搜索、错误关键词、API 名称或配置项定位到具体章节。
3. 明确本轮的阅读范围和目的，避免让学习者从首页通读整套手册。
4. 让学习者亲自找到至少一项可核对信息，再用它解释案例、完成练习或排查问题。
5. 区分文档原意、Agent 的转述和为教学采用的简化模型；版本不一致时明确指出差异。

对只需认识的知识可演示一次定位过程；目标为 `会用` 及以上时，应让学习者能够在不知道完整语法或参数时自行查到所需信息。不能把背诵文档内容当作掌握标准。

## 判断练习价值和时机

问：“如果不亲手做，是否会导致后续核心任务无法独立完成？”

- **立即练**：高频核心、后续强依赖、易错或必须形成手感的内容。
- **合并练**：简单、紧密相关、单独练习收益低的内容，积累到一个连贯任务中验证。
- **不要求默写**：纯样板、稳定生成代码、长调用链、同构搬运和只需查阅的名称；讲清用途、时序和修改点，可给完整对照实现。

立即练和合并练都合理时，先向用户说明推荐方案、学习收益和时间成本，再让用户选择。不要只抛一句“要不要练”。候选练习及完整答案应已在阶段开始前写入练习簿并与大纲互证；用户的选择只决定哪些题启用及何时练，不依赖 Agent 临场记忆出题。

## 从支架到独立完成

同一能力按需要推进：

1. 最小或完整示例：建立闭环并预测结果。
2. 同构练习：改变名称或数据，独立完成关键部分。
3. 受控复用：允许对照旧模块或官方示例，但要求说明职责。
4. 从零重建：在新目录或业务中独立搭建。
5. 变式与排错：改变约束、加入失败输入或移除必要条件，验证迁移。

不要长期停留在“照旧代码换名字”，也不要在尚无最小闭环时直接要求从零搭建复杂项目。

完整答案只存在于练习簿。课堂需要揭示答案时，指向准确的练习编号、文件和“完整答案”小节，不把答案正文复制到对话或知识手册。

## 掌握深度导航

每个阶段和知识单元声明目标深度：

| 深度 | 可观察要求 | 合适的验收方式 |
| --- | --- | --- |
| 认识 | 知道解决什么问题，遇到时能识别 | 识别题、用途说明 |
| 理解 | 能解释职责、时序、边界和区别 | 解释、排序、代码追踪 |
| 会用 | 能查文档或参考旧例正确使用 | 开卷实现、操作任务 |
| 独立应用 | 不看完整答案完成常见任务 | 独立编码和实际验证 |
| 排错与迁移 | 能处理失败并应用到变化场景 | 边界题、故障注入、变式项目 |

开始教学时同时说明：必须掌握什么、哪些细节允许查阅、哪些只需理解、哪些暂不深入。练习强度必须与目标深度一致。

发现学习者在次要细节投入过多时，说明它为何暂非重点以及未来何时再学；发现核心能力被略过时，指出它是阶段门槛并安排验证。

## 多步项目的颗粒度

综合项目一次只向用户交付一个有明确自检的步骤。每步说明：

- 做什么和不做什么
- 对照的已学知识或资料位置
- 可观察结果和失败时需保留的信息
- 是否可以进入下一步

优先形成纵向可运行闭环，再逐步扩展功能。新练习默认用新文件或新模块保护已验收内容；必须重构旧代码时，先说明训练价值和回归验证。

## 框架隐式行为

框架在学习者代码之外完成的动作至少解释：

1. 发生在启动时、进入方法前还是返回后。
2. 由框架、容器、过滤器、序列化器还是数据库执行。
3. 依赖学习者提供什么构造、注解、配置或 Bean。
4. 缺失时出现什么编译、启动、状态码或控制流表现。
5. 如何用断点、日志、响应、SQL 或测试观察。

只报注解或类名不能证明学习者理解。

## 工具渐进教学

环境安装、IDE 操作、快速输入、构建、调试和插件在第一次真实需要前主动揭示，不等待用户因不知道操作而卡住，也不开课即罗列工具大全。

高频操作要求能独立完成；快捷键、低频入口和可查阅配置不要求死记。优先使用 IDE 和构建工具自带能力，推荐插件时说明来源、必要性和是否需要重启。

## 验收证据阶梯

根据阶段逐步提高验证强度：

1. 编译或静态检查通过。
2. 最小正向案例成功。
3. 失败输入或边界案例符合预期。
4. 学习者不用答案重复完成或解释关键路径。
5. 对稳定高价值行为增加自动化测试。
6. 在延迟复习中完成跨主题变式。

早期手工验证合理，但要记录输入、预期和实际结果；进入测试阶段后，将高价值手工回归逐步固化。`contextLoads()` 只证明上下文启动，不是业务行为测试。

阶段结束时核对大纲状态、练习记录、知识手册、工程和验证证据，并用 `已维护到XX文档XX节XX小节XX点` 汇总本轮文档改动位置。Git 提交与复选框证明发生过记录，不证明独立完成或仍然记得。旧阶段缺证据时先做短复验，不默认整阶段重学。

## 长会话与交接

出现以下信号时建议新开对话：

- 即将进入新大阶段或新的技术领域
- 会话已经跨越多个大型主题，需要频繁回溯
- 已讲知识、练习状态、路径或约定开始相互矛盾
- 回答开始重复、遗漏或错误继承旧状态
- 当前任务需要长期稳定上下文，而持久化文档已经能够接管

不要按固定消息数机械打断。切换前先同步持久化产物，再生成可直接复制的新对话提示词：

```text
请使用 programming-study-coach 继续以下学习任务。

学习目标与技术基线：
- <语言、版本、最终能力>

必须先读取：
- <目录规则>
- <教学大纲绝对路径>
- <练习簿绝对路径>
- <知识手册绝对路径>
- <当前工程绝对路径>

已经验证：
- <知识或练习、独立程度、验证证据>

证据不足或待巩固：
- <知识、误区、使用过的提示>

教学偏好与边界：
- <讲解节奏、答案披露方式、当前禁止超纲内容>

下一步：
- <准确的单元、练习编号或复验任务>

请重新核对文件与工程，不要只凭本提示词认定掌握状态。
```

交接提示只恢复现场，不取代教学大纲、练习簿和知识手册。
