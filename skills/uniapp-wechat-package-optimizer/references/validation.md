## 2026-09-22 验证环境

Windows / PowerShell，本机 Node `22.22.0`、npm `10.9.4`。Skill 内部依赖锁定官方 npm registry 实际可安装的 `miniprogram-ci 2.1.31`；未仅凭较新文档推定接口。以下是本次具体组合的测试结果，不是所有历史编译器版本的兼容认证。

| 工程 | 实际依赖版本 | 生产构建 |
|---|---|---|
| Vue 2 CLI | Vue 2.6.14、Vue CLI 5.0.9、Webpack 5.111.1、DCloud 2.0.2-5020620260917001 | `build:mp-weixin` 成功 |

两套工程基于公开的 [DCloud uni-preset-vue](https://github.com/dcloudio/uni-preset-vue) master / vite 模板实际创建、安装依赖、执行编译。Vue 2 生成器遗留的 `transpileDependencies: true` 调整为空数组，并补齐官方模板的 PostCSS 配置以完成构建。这些是测试工程适配，不是要求 Skill 自动修改所有业务工程。

测试工程、锁文件、原始源码快照和报告保留在维护仓库根 `test/uniapp-wechat-package/` 中，由现有 `.gitignore` 忽略，不随 Skill 分发。安装到其它仓库后不会附带这些测试工程；复测时需按下述方法另行创建。

## 真实构建与优化闭环

两套工程都有主包页、一个分包页、共享模块、分包独占模块、重复静态资源及未引用资源。样例数据已用注释标为测试数据。优化操作是调整分包页引用以复用同一资源，并从源码移除一份重复资源和一份确认未使用的资源，再执行完整 production 构建。

| 口径：本地文件字节 | Vue 2 优化前 | Vue 2 优化后 | Vue 3 优化前 | Vue 3 优化后 |
|---|---:|---:|---:|---:|
| 总量 | 184,071 | 183,431 | 75,839 | 75,152 |
| 主包 | 183,052 | 182,414 | 75,040 | 74,355 |
| package-a | 1,019 | 1,017 | 799 | 797 |
| 文件数 | 20 | 18 | 21 | 19 |

统一报告的文件数和字节总量均与磁盘实测一致。两套 `--baseline` 对比均保持相同工具、生产构建口径、配置和依赖锁，正确记录文件删除及内容变化；Vue 2 还识别到了 WXML 字节数不变但 SHA-256 改变的情况。

这验证的是采集、归属、去重、报告和优化复测流程；测试文件很小，不能据此宣称真实业务项目的节省比例。**尚未执行真实微信预览，所有 packedBytes 为 null，最终微信打包体积未验证。**

## 回归与独立检查

`scripts/` 目录的 Node 测试覆盖核心数据处理、报告生成和真实 SDK 的无密钥本地调用：

- 精确分包归属、相近根路径、显式分包名与 `__APP__` / `__FULL__` 映射。
- 缺失 packedBytes 保持 null；未关联文件和重复候选不直接判定可删除。
- Windows SDK 正反斜杠别名去重、分包尾斜杠规范化、冲突信息拒绝。
- 新增/删除/同体积变化，混合构建或 SDK / 配置口径提示。
- 目录穿越拒绝、Vue 2 / Vue 3 工程识别、非 CLI 工程拒绝。
- JSON 嵌入转义（包括 `</script>` 和 `$&` 等替换字符）、BOM、空数据、禁止覆写已有输出、任意 cwd 调用。
- 实际调用官方 `analyseCode`、`checkCodeQuality`，不使用真实上传密钥。

另在隔离的 `test/uniapp-wechat-package/report-dom/` 使用 jsdom 26.1.0 做了 17 项 DOM 集成测试：真实 Vue 3 数据的包筛选、搜索、文件与上下游依赖导航、目录嵌套与树图点击，以及空状态、模块错误、前后对比和标题转义。树图验证“代码包 → 主包/分包 → 具体目录和文件”的强制层级，画布顶层仅有包节点，真实数据中的 16 个主包文件和 5 个分包文件全部位于各自包区块，分包根路径不会重复；不同包中的同名目录保持独立，包归属仅由一级包节点表达，子目录和文件不生成重复包标签。目录交互覆盖连续下钻、面包屑导航、文件点击不误触目录、完整目录边框、重排保留位置和切换包重置目录；同时核对根层级统计栏的文件数、各级目录和单文件大小、目录透明与文件填充色、目录体积强调及文件体积常规字重。合成边界数据覆盖零字节、长中文文件名、恶意文本、不同目录同名文件，并验证 607 个文件在同一固定视图中全部渲染；另以 320px 窄视口验证 47 个同层文件同时存在、无分页控件、标签单行省略和扩大视口后的重排。递归核对布局样式中的正尺寸、区块分隔、同级无重叠、子块不越父边界及画布不超出固定视口。质量检查测试覆盖官方结果中文展示、通过与未通过状态、未知规则和原始证据保留。合成数据仅用于回归，不冒充真实项目数据。jsdom 模拟视口尺寸与 `scrollIntoView`，几何断言基于计算写入的样式，不代表浏览器截图、字体、像素或响应式视觉验收。本机自动浏览器阻止了 `file://` 访问，没有尝试绕过该策略。

独立检查还使用多分包有效产物实调 SDK，验证了无密钥时默认不预览、输出不泄漏密钥路径、已有目录和产物内部输出被拒绝；已有产物对比会提示无法确认生产构建。

## 已发现并处理的 SDK 差异

`miniprogram-ci 2.1.31` 在 Windows 上可能把同一文件以正斜杠和反斜杠各列一遍，导致原始文件和质量统计重复。统一层已去重并保留原始结果、增加警告；不可再把原始质量扫描中的同文件别名当无用代码。具体行为见 [执行协议](runtime.md#windows-sdk-路径兼容)。

报告依赖导航分别使用 `deps.moduleId` 与 `parentDeps.originModuleId`；不能把父引用的 `moduleId` 当调用者，否则会跳回自身。

## 后续复测

1. 确认目标操作系统和本机 Node，按 Skill 白名单取用，在 `scripts/` 安装锁定依赖并运行 `npm test`。
2. 根据 DCloud 官方 CLI 模板分别新建 Vue 2 / Vue 3 项目，保存锁文件，加入可追溯的主包、分包、共享和独占引用。
3. 实际 production 构建后运行分析，与物理文件数量/字节核对；不要手写 dist 冒充 uni-app 编译。
4. 对源码作一项可证实优化，重新构建并用 `--baseline` 复测，保留原始报告。
5. 使用获得授权的 AppID、包外密钥路径和 IP 白名单执行 `--preview`，再验证真实 `subPackageInfo`。本次尚未完成此步。
6. 对实际使用的页面和资源做真机回归。本次测试用 SVG 只覆盖静态资源复制/分析，不代表微信真机图片渲染已通过。

自动化合成夹具不能冒充真实构建结果。提交业务代码前，仍应按项目规则清理或注释临时 mock 数据；测试样例仅留在隔离测试目录。
