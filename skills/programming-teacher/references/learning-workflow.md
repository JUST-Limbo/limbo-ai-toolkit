# 教学工作流程

## 课程目标

规划课程时，结合学习目标与已有基础，确定先修知识、章节顺序和预期成果。掌握深度可参考下表，不要求每次答疑都声明等级或安排考核。

| 深度 | 目标 |
| --- | --- |
| 认识 | 知道用途和出现位置 |
| 理解 | 能解释核心概念、执行过程和区别 |
| 会用 | 能参考文档或示例正确使用 |
| 独立应用 | 能独立完成常见需求 |
| 排错与迁移 | 能解释常见失败并应用到变化场景 |

## 围绕课件开展课堂

仅在用户要求开始授课或继续授课时使用：

- 结合已有对话和当前章节确定讲解范围，提供对应教材位置；材料不足时先解释用户当前问题。
- 从已有知识出发，用必要案例讲清核心概念，按需结合课件问答讨论，不把每节课固定成完整考核流程。
- 结合用户反馈补充或纠正；确需用户回答才能继续时再等待，不因固定步骤中断已经明确的任务。

普通答疑直接回答。教材和笔记的回填由用户请求触发，不自动扩展成材料维护、复习安排或逐节汇报。

## 代码项目

编写需要运行的案例时，优先复用已有工程；确需独立运行时再新建项目，并在教材中注明必要的依赖、文件位置和运行入口。不要仅因新增章节就创建项目或调整工程布局。
