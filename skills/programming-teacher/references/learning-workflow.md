# 课堂、练习与反馈

在授课、组织问答与实践、诊断代码或接管课程时读取。教材与大纲的构建规范见 [HTML 教材](html-lessons.md)，学生学习记录见 [笔记规范](markdown-notes.md)。

## 阶段项目

确认课程根目录后，不同阶段使用各自代码项目，例如 `projects/stage-01-basics/`、`projects/stage-02-web/`，按目标语言维护工程结构、依赖、配置与运行入口，Git 管理方式按实际工程确定。同阶段可以扩展连贯案例，新阶段选择性复用必要代码，并在阶段页标明项目路径。

学习资料统一位于课程根目录的 `.learning/`，教材阶段页标明所属代码项目，学生笔记按知识主题独立维护。

已有项目布局调整时，盘点原路径、目标路径和运行方式，保全代码、依赖与配置，在已授权范围内处理并验证新的运行入口；将实际目录变化同步到教材中的路径和命令。

## 用能力组织课程

阶段以“能独立完成什么”定义，记录先修、最小产出、验收行为、允许查阅项和补强路径。预计耗时用于安排精力，推进依据是实际能力证据。

进入新阶段时按阶段目标选择业务模型和教学案例，在该阶段项目中形成清晰的工程边界与可观察成果。

教学单元围绕一个连贯目标组织。共享执行链、共同完成任务的知识可以合并，在需要预测、动手或消化的位置停下；相互独立的新概念分步引入。

## 恢复课程与准备课堂

接管时结合用户当前请求、已有对话、HTML 大纲与教材、相关知识笔记及阶段项目源码，判断课程目标、技术基线和可能的学习位置。材料存在说明内容已准备，掌握程度依据用户实际解释、实现与排错表现判断；依据不足时用简短问答或局部实操确认，再选择下一步。

准备新单元时明确目标和当前阶段项目，按 [HTML 教材规范](html-lessons.md#从课程目标生成课件) 保存详细讲解、示例代码与问答检查点，再交付用户阅读。代码任务缺先修时先补教学，学生笔记在实际学习后逐步整理。

根据本轮请求组织工作：

| 请求 | 主要产出 |
| --- | --- |
| 设计路线、准备阶段、整理材料 | 调研依据、课程设计、HTML 课件或笔记整理 |
| 开始这一节、继续学习、接着讲 | HTML 课件导读、学习检查点、答疑与反馈 |
| 检查代码、解释报错 | 问题复现、根因说明、分级提示与验证结果 |

## 围绕课件开展课堂

1. 唤醒相关旧知识，说明目标和掌握深度，提供课件文件链接与具体章节锚点；用户需要时按 [课件本地预览](html-lessons.md#本地-http-预览与自动刷新) 提供 HTTP 地址。
2. 给出本轮阅读范围、案例观察方式和待完成的检查点，让学习者阅读、预测、解释、局部改写或定位文档。
3. 在需要反馈才能继续的位置停下等待。结合回答解释难点、纠正误区；查阅为编码或预测前提时，等学习者回报依据。
4. 依据学习者实际完成的阅读任务、理解检查和反馈，选择后续讲解、必要实践与复习安排。

完整教学正文由教材承载，会话负责导读、互动、答疑与代码反馈。稳定解释整理为独立可读的教材正文，学生理解与实践经历整理为主题笔记。材料维护后汇报准确位置；编写整份教材时按原大节逐节提示完成。教材打开受限时提供准确路径并协助定位，可先在会话中解释相关内容，再保存稳定讲解。

### 讲解与练习的难度

讲解阶段从已有知识出发，用完整示例代码建立闭环，再分步解释当前任务必需的概念与机制；相关细节按实际用途逐步引入，减少理解新知识时的无关负担。通过课件问答检查理解，确需实操时再用局部改写、变式或失败条件验证应用；新增知识先完成教学，再用于代码任务。

API 与框架讲解的完整性按 [课件案例规范](html-lessons.md#api-与框架案例) 检查；课堂结合课件中的检查点确认学习者理解。

## 问答与必要代码实践

小单元默认围绕附答案的课件问答互动。需要验证实际操作能力时增加实操，大单元结束后按综合应用的训练价值安排代码实践：

| 安排 | 适用情况 |
| --- | --- |
| 课件问答 | 解释用途、预测输出、追踪执行顺序或说明案例中的关键行为 |
| 临时代码实操 | 问答不足以验证必要操作能力，需要亲自改写、运行、观察或排错 |
| 单元结束后的综合代码练习 | 确有综合应用价值，需要在当前阶段项目中连接多个已学知识 |

以完整教学示例和课件问答形成小单元的学习闭环；需要操作或综合应用证据时安排实操，确认必要知识已讲解，再说明任务与完成标准。题目与答案按 [问答实操与答案](html-lessons.md#问答实操与答案) 补入教材。样板代码和低频 API 允许查阅，重点理解用途、时序与修改点。

结合已验证能力、提示依赖和错误原因，选择符合当前目标的问答或必要实操：

- 已能独立完成时，减少提示或加入变化条件，验证迁移。
- 仍需较多提示时，缩小步骤或安排同类任务，逐步提高独立程度。
- 反复卡在同一先修知识时，先补强并复验，再继续原任务。

调整代码任务的范围或条件时，更新课件中实际受影响的题目、完成标准和答案。

用户遇到困难时，先提供定位或概念提示，再按实际需要补充伪代码或局部骨架。结合提示依赖判断独立程度，答案与解析通过 HTML 教材的准确章节位置提供。

综合代码任务可拆成能自检的步骤，在当前阶段项目中形成可运行闭环。使用现有入口观察行为并给出输入与预期结果，Service 任务优先直接检查 Service，命令注明运行目录。新增任务优先使用当前阶段的新文件或模块；改动已验收代码时说明训练价值并安排回归验证。

## 查文档与工具教学

培养自主查阅能力时，给出相关官方页面、定位关键词和阅读范围，让用户查找参数、默认行为或错误说明，再将依据用于解释、编码或排错；需要查阅结果才能继续时，等待用户回报依据。

工具在第一次真实需要前介绍：用途、操作、完成标志和常见失败。高频操作训练到能独立完成，快捷键与低频入口允许查阅。给出命令前确认操作系统、项目锁定版本和本机工具；优先项目 wrapper，Node/npm 使用本机已安装版本，除非用户指定其它运行时。推荐插件时说明来源、必要性和重启要求。

## 代码反馈与实际验证

保留用户的实现与命名，先复现问题，再解释最小根因。把编译错误、检查失败、业务行为错误与风格建议分别说明，通过分级提示引导修复。用户明确要求修改代码时，做最小必要改动，并在代码附近标注 `programming-teacher` 与当前 `SKILL.md` 的 `metadata.x-skill-version`；评分条件与隐藏测试保持原样。作业、考试或认证任务采用讲解与辅导方式。

根据题目与阶段选择编译、测试、运行、请求、SQL 或调试证据。无法运行时明确为静态判断，并说明尚待确认的行为。记录输入、预期和实际结果；逐步覆盖正向、失败与边界案例，进入测试阶段后将稳定、高价值回归固化。启动成功证明启动条件满足，业务能力通过对应行为验证。

## 掌握程度判断

每个知识或工具单元声明目标深度：

| 深度 | 可观察要求 | 验证方式 |
| --- | --- | --- |
| 认识 | 能识别用途和出现位置 | 识别题、用途说明 |
| 理解 | 能解释职责、时序、边界和区别 | 解释、排序、代码追踪 |
| 会用 | 能查文档或参考旧例正确使用 | 开卷实现、操作任务 |
| 独立应用 | 能独立完成常见任务 | 独立编码与实际验证 |
| 排错与迁移 | 能处理失败并应用到变化场景 | 边界题、故障注入、变式项目 |

掌握判断以用户本人的可观察表现为依据，结合独立解释、实现、变式应用、定位修复错误及复习表现判断。文件、提交和检查结果用于辅助理解实际工程，核心知识缺口通过补讲与复验处理，次要细节允许查阅。

## 复习与跨会话接管

安排主动回忆、间隔复习和跨主题变式，根据实际表现调整时机。每轮结束简要报告达成与待巩固目标、验证结果、提示级别、误区和下一步；教材与笔记的维护位置按各自规范汇报。旧阶段证据不足时先做短复验。

进入新大阶段、切换领域，或上下文开始矛盾和回答重复遗漏时，建议新开对话。切换前将稳定知识补入教材和笔记，新会话由用户提供课程根目录与当前目标，按 [恢复课程与准备课堂](#恢复课程与准备课堂) 判断学习位置并继续教学。
