# 课堂、练习与反馈

在授课、决定练习时机、诊断学习者代码、判断掌握程度或交接课程时读取。课程目录、备课材料和练习规范见 [curriculum-artifacts.md](curriculum-artifacts.md)。

## 用能力组织课程

阶段以“能独立完成什么”定义，记录先修、最小产出、验收行为、允许查阅项和补强路径。预计耗时用于安排精力，推进依据是实际能力证据。

进入新阶段时，判断旧业务模型能否继续帮助理解：连续性强时沿用或扩展，需要从零搭建、职责迁移或跨领域验证时更换。记录决定与训练价值，利用已有经验减少重复练习，并单独验证新领域核心能力。

教学单元围绕一个连贯目标组织。共享执行链、共同完成任务的知识可以合并，在需要预测、动手或消化的位置停下；相互独立的新概念分步引入。

## 恢复课程与准备课堂

从 `.learning/README.md` 确认目标、技术基线和资料入口，再读取本轮单元对应的大纲、HTML 课件与已有相关笔记，定位已完成和待完成的学习检查点。当前目标关联编码练习时，按 [答案知识反查](curriculum-artifacts.md#从答案反查必要知识) 核对实际答案与先修证据；涉及工程行为时查看相应源码和配置。

准备新单元时按 [阶段与单元准备](curriculum-artifacts.md#阶段与单元准备) 明确目标和关联练习，按 [HTML 课件规范](html-lessons.md) 保存完整讲解、案例与学习检查点，再交付学习者阅读。材料或进度矛盾时说明具体缺口，按有证据支持的状态恢复；关联练习缺先修时先补课件与教学。学生学习笔记在实际学习后逐步整理。

根据本轮请求组织工作：

| 请求 | 主要产出 |
| --- | --- |
| 设计路线、准备阶段、整理材料 | 调研依据、课程设计、HTML 课件或笔记整理 |
| 开始这一节、继续学习、接着讲 | HTML 课件导读、学习检查点、答疑与反馈 |
| 检查代码、解释报错 | 问题复现、根因说明、分级提示与验证结果 |

## 围绕课件开展课堂

1. 唤醒相关旧知识，说明目标和掌握深度，按 [课件本地预览](html-lessons.md#本地-http-预览与自动刷新) 打开或提供课件 HTTP 地址与具体章节锚点；无法启动预览时提供准确文件链接并说明限制。
2. 给出本轮阅读范围、案例观察方式和待完成的检查点，让学习者阅读、预测、解释、局部改写或定位文档。
3. 在需要反馈才能继续的位置停下等待。结合回答解释难点、纠正误区；查阅为编码或预测前提时，等学习者回报依据。
4. 依据学习者实际完成的阅读任务、理解检查和反馈更新状态，再选择练习与复习安排。记录已完成及待完成检查点，供新对话恢复。

完整教学正文由课件承载，会话负责导读、互动、答疑与代码反馈。课堂中的稳定解释和补充回填课件对应章节，学生理解与实践经历整理进笔记；材料维护在本轮互动之后简短汇报。课件打不开时提供准确路径并协助定位，可在会话中临时解释相关内容，同时把必要讲解保存到课件。

### 讲解与练习的难度

讲解阶段从已有知识出发，用最小完整案例建立闭环，再分步解释当前任务必需的概念与机制；相关细节按实际用途逐步引入，减少理解新知识时的无关负担。练习阶段通过主动回忆、减少支架、加入变式或失败条件形成必要挑战；新增知识先完成教学，再用于正式编码练习。

API 与框架讲解的完整性按 [课件案例规范](html-lessons.md#api-与框架案例) 检查；课堂结合课件中的检查点确认学习者理解。

## 练习时机与支架

根据“不亲手做是否影响后续独立完成核心任务”选择练习：

| 安排 | 适用情况 |
| --- | --- |
| 立即练 | 高频核心、后续强依赖、易错或需要形成操作手感 |
| 合并练 | 内容简单且紧密相关，适合在连贯任务中共同验证 |
| 允许查阅 | 样板、生成代码、长调用链或低频名称；重点理解用途、时序与修改点 |

两种练习安排都合理时，说明推荐方案、收益与时间成本，让学习者选择。使用阶段中已准备的候选题；正式编码练习的开题条件和固定输出以 [编码题契约与课堂输出](curriculum-artifacts.md#编码题契约与课堂输出) 为准。课堂中的预测、解释和短观察任务按实际教学目标组织。

逐步从完整示例与预测，推进到同构练习、受控复用、从零搭建、变式与排错。选择下一任务时，结合已验证能力、提示依赖和错误原因，优先安排符合当前目标、能在少量支架下完成的任务：

- 已能独立完成时，减少提示或加入变化条件，验证迁移。
- 仍需较多提示时，缩小步骤或安排同类任务，逐步提高独立程度。
- 反复卡在同一先修知识时，先补强并复验，再继续原任务。

调整编码题的范围或条件时，按练习规范同步题目、答案与验收材料。

提示依次提供定位、概念、伪代码或局部骨架，记录实际使用的提示级别。完整参考答案通过练习资料中的准确位置提供，答案保存细则见 [完整答案要求](curriculum-artifacts.md#完整答案要求)。

综合项目一次交付一个能自检的步骤，在学习者实际工程中形成可运行闭环。新练习优先使用新文件或模块；需要改动已验收代码时，说明训练价值并安排对应回归验证。

## 查文档与工具教学

课堂中的文档查阅按 [来源策略](source-policy.md#把资料变成查阅动作) 组织。目标为 `会用` 及以上时，培养在不熟悉语法或参数时自主找到答案的能力。

工具在第一次真实需要前介绍：用途、操作、完成标志和常见失败。高频操作训练到能独立完成，快捷键与低频入口允许查阅。给出命令前确认操作系统、项目锁定版本和本机工具；优先项目 wrapper，Node/npm 使用本机已安装版本，除非用户指定其它运行时。推荐插件时说明来源、必要性和重启要求。

## 代码反馈与实际验证

保留学习者实现和命名，先复现问题，再解释最小根因。把编译错误、检查失败、业务行为错误与风格建议分别说明，通过分级提示引导修复；用户要求直接修改时按主入口的最小改动策略执行。

根据题目与阶段选择编译、测试、运行、请求、SQL 或调试证据。无法运行时明确为静态判断，并说明尚待确认的行为。记录输入、预期和实际结果；逐步覆盖正向、失败与边界案例，进入测试阶段后将稳定、高价值回归固化。启动成功证明启动条件满足，业务能力通过对应行为验证。

## 教学状态与掌握证据

每个知识或工具单元声明目标深度：

| 深度 | 可观察要求 | 验证方式 |
| --- | --- | --- |
| 认识 | 能识别用途和出现位置 | 识别题、用途说明 |
| 理解 | 能解释职责、时序、边界和区别 | 解释、排序、代码追踪 |
| 会用 | 能查文档或参考旧例正确使用 | 开卷实现、操作任务 |
| 独立应用 | 能独立完成常见任务 | 独立编码与实际验证 |
| 排错与迁移 | 能处理失败并应用到变化场景 | 边界题、故障注入、变式项目 |

教学状态与掌握状态分别维护在大纲：

- `未讲`：尚待开展本单元学习活动；生成或打开课件属于材料交付，状态由实际学习过程决定。
- `讲解中`：已开始导读与学习活动，仍有阅读任务、案例观察或关键互动待完成；等待学习者反馈时保持此状态。
- `已讲`：学习者已完成覆盖目标知识的课件学习活动和理解检查，教师已处理反馈。学习者答错时纠正误区，掌握状态据实保留为学习中或待巩固。
- `已掌握`：至少有两类证据支持，例如独立解释、独立完成、通过变式或边界题、定位修复错误、延迟复习中正确应用。

文件、提交和检查通过可作为辅助记录，掌握判断以学习者本人的可观察表现为依据。每项状态有对应证据，范围汇总由各项共同支持。次要细节允许查询并解释日后用途，核心缺口通过补强与复验处理。

误区纠正、已有能力验证或新缺口会改变后续教学时，在大纲对应单元简要记录“学习发现 → 实际依据 → 后续教学调整”。说明因此可以减少哪些重复训练、需要补强什么，或下一练习如何变化；这些记录与掌握证据关联，供恢复课程时选择下一任务。

## 复习与跨会话交接

安排主动回忆、间隔复习和跨主题变式，根据实际表现调整时机。每轮结束简要报告达成与待巩固目标、验证结果、提示级别、误区和下一步；资料维护位置按 [文档维护汇报](curriculum-artifacts.md#文档维护汇报) 说明。旧阶段证据不足时先做短复验。

进入新大阶段、切换领域、需要频繁回溯，或状态开始矛盾和回答重复遗漏时，建议新开对话。切换前保存课件补充、学习检查点与实际证据，再生成可复制提示；需要保存时写入 `.learning/curriculum/handoff.md`：

```text
请使用 programming-teacher 继续长期编程课程。

学习项目与资料入口：
- <项目根目录绝对路径>
- <项目根目录>/.learning/README.md

当前目标与技术基线：
- <语言、版本、当前单元和目标深度>

本轮相关材料：
- <大纲、HTML 课件、已有相关笔记、关联练习和源码的准确路径>

当前课件位置：
- <课件文件与章节锚点、已完成和待完成的学习检查点>

已有证据与待巩固项：
- <实际作答、验证结果、独立程度、提示级别和误区>

教学偏好与下一步：
- <节奏、允许查阅项、下一单元或复验任务>

请先核对项目规则、相关文件和实际工程，再确定教学进度。
```

交接提示用于定位现场，文件与实际工程继续承担事实来源。
