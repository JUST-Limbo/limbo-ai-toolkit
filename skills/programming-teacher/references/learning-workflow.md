# 教学工作流程

在授课、组织问答、诊断代码或接管课程时读取。教材与大纲的构建规范见 [HTML 教材规范](html-lessons.md)，Markdown 笔记维护见 [Markdown 笔记规范](markdown-notes.md)。

## 代码项目

代码按案例或项目需要组织，可复用已有工程，或在需要独立运行时新建项目。按目标语言维护工程结构、依赖、配置与运行入口，在相关教材中标明项目路径，Git 管理方式按实际工程确定。

Markdown 笔记按课程维护主线文档，并按需配套专题文档，具体组织见 [文档拆分策略](markdown-notes.md#文档拆分策略)。

已有项目布局调整时，盘点原路径、目标路径和运行方式，保全代码、依赖与配置，在已授权范围内处理并验证新的运行入口；将实际目录变化同步到教材中的路径和命令。

## 用能力组织课程

课程目标以“能独立完成什么”定义，明确先修、预期成果与掌握要求，据此选择业务模型和教学案例。预计耗时用于安排精力，推进依据是实际能力证据。

教学单元围绕一个连贯目标组织。共享执行链、共同完成任务的知识可以合并，在需要预测、讨论或消化的位置停下；相互独立的新概念分步引入。

## 围绕课件开展课堂

1. 唤醒相关旧知识，说明目标和掌握深度，提供课件文件链接与具体章节锚点；用户需要时按 [课件本地预览](html-lessons.md#本地-http-预览与自动刷新) 提供 HTTP 地址。
2. 给出本轮阅读范围、案例观察方式和待完成的检查点，让学习者阅读、预测、解释或定位文档。
3. 在需要反馈才能继续的位置停下等待。结合回答解释难点、纠正误区。
4. 依据学习者实际完成的阅读任务、理解检查和反馈，选择后续讲解与复习安排。

完整教学正文由教材承载，会话负责导读、互动、答疑与代码反馈。稳定解释整理为独立可读的教材正文，学习者的理解与实践经历整理为主题笔记。材料维护后汇报准确位置；编写整份教材时按原大节逐节提示完成。教材打开受限时提供准确路径并协助定位，可先在会话中解释相关内容，再保存稳定讲解。

### 讲解深度

讲解从已有知识出发，用完整示例代码建立闭环，再分步解释当前任务必需的概念与机制；相关细节按实际用途逐步引入，减少理解新知识时的无关负担。通过课件问答检查理解。

API 与框架讲解的完整性按 [课件案例规范](html-lessons.md#api-与框架案例) 检查；课堂结合课件中的检查点确认学习者理解。

## 课件问答

围绕课件问答解释用途、预测输出、追踪执行顺序或说明关键行为。题目与答案按 [课件问答与答案](html-lessons.md#课件问答与答案) 补入教材。

根据回答调整提示与讲解；反复卡在先修知识时先补讲，再回到原问题。

## 掌握程度判断

每个知识或工具单元声明目标深度：

| 深度 | 可观察要求 | 验证方式 |
| --- | --- | --- |
| 认识 | 能识别用途和出现位置 | 识别题、用途说明 |
| 理解 | 能解释职责、时序、边界和区别 | 解释、排序、代码追踪 |
| 会用 | 能查文档或参考旧例正确使用 | 开卷实现、操作任务 |
| 独立应用 | 能独立完成常见任务 | 独立编码与实际验证 |
| 排错与迁移 | 能处理失败并应用到变化场景 | 边界题、故障注入、变式项目 |

掌握判断以用户本人的可观察表现为依据，结合独立解释、实现、变式应用、定位修复错误及复习表现判断。文件、提交和检查结果用于辅助理解实际工程，核心知识缺口通过补讲与复验处理，次要细节允许查阅。
