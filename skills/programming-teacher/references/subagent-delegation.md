# 子智能体委派体系

## 何时读取

当任务包含可独立并行的课程调研、文档定位、教学产物审计、练习或知识手册草稿、学习者代码诊断、阶段状态盘点或交接信息提取，并且当前运行环境提供子智能体工具时读取。

## 委派目标

子智能体只承担边界明确、结果可复核的子任务。主 Agent 负责理解学习者、作出教学决策、整合证据并维护最终事实源。委派不能扩大用户授权，也不能因为可以并行就制造额外工作。

满足以下条件之一才委派：

- 两个以上子任务彼此独立，并行执行能明显缩短等待时间。
- 独立复核能明显降低课程超纲、产物断链或错误归因风险。
- 单个子任务需要大量搜索、跨文件读取或证据整理，隔离上下文能减少主会话负担。

以下情况直接由主 Agent 完成：

- 单个短概念答疑、一次小范围文档修改或其它低成本任务。
- 下一步依赖上一结果，无法与主 Agent 的有效工作并行。
- 子任务需要持续观察学习者回答、选择提示等级或当场调整教学节奏。
- 拆分后的说明、等待和整合成本预计不低于直接完成。

## 可委派任务

| 任务 | 子智能体职责 | 主 Agent 保留职责 |
| --- | --- | --- |
| 课程与资料调研 | 查找官方、大学或成熟公开课程，记录版本、章节、采用价值和局限 | 比较方案并决定路线 |
| 文档定位 | 找到当前知识点的官方页面、章节、检索词和版本范围 | 设计学习者的查阅动作 |
| 产物一致性审计 | 检查 `K-*`、`T-*`、`E-*` 双向引用、超纲内容、断链和状态矛盾 | 决定修改大纲、练习簿还是手册 |
| 练习与答案草稿 | 在给定知识边界内起草互不重叠的 `E-*` 文档或 `answers/<E-*>/` 实际代码文件，并维护文件清单 | 控制难度、跨题顺序和最终写入 |
| 知识手册草稿 | 按已确定提纲起草独立主题或独立文件 | 统一教学口径、链接和结构 |
| 代码诊断 | 读取规则与工程、复现错误、收集输出、区分失败类型并提出根因候选 | 选择提示等级并向学习者讲解 |
| 状态盘点与交接提取 | 汇总路径、已学内容、证据、误区和待办 | 判断掌握状态并生成最终交接内容 |

参考答案默认只做静态完整性与路径一致性检查，不为每题委派编译、运行、测试或答案运行状态记录。只有用户明确要求、真实输出是当前判断所必需，或已有环境下验证成本很低时，才把运行验证作为独立子任务。

委派练习草稿前，主 Agent 先为每个分支写清 `E-*` 编号、练习文档路径、唯一的 `answers/<E-*>/` 输出目录、文件清单职责、独占训练目标、允许共享的先修知识、与其它题的依赖和禁止重复覆盖的内容。题材不同不等于训练目标不同；不能把重复练习留到最终审计时才发现。

## 不可委派的最终责任

主 Agent 不得把以下责任交给子智能体后直接照单全收：

- 与学习者连续互动、唤醒旧知识、调整讲解顺序和逐级提示。
- 决定阶段边界、练习模型、立即练或合并练，以及是否进入下一阶段。
- 根据多类证据判定“已掌握”。
- 解决来源冲突、决定课程取舍和确认最终事实。
- 同时写入教学大纲、练习文档、同一答案目录、知识手册等共享事实源。
- 对子智能体结果进行复核、整合并向用户负责。

## 模型与思考强度自主选择

主 Agent 在每次委派前读取子智能体工具实际列出的可用模型、能力描述和支持的思考强度。不要写死或猜测不可用的模型名；用户没有指定时，不询问用户选择，由本 Skill 按任务自主决定。

### 选择模型

1. **轻量任务**：精确摘取、文件清单、状态归类、链接检查、固定格式转换。选择当前可用的快速或经济型模型。
2. **标准任务**：资料调研、独立主题草稿、普通一致性审计、局部代码诊断。选择当前可用的均衡型通用或编码模型。
3. **复杂任务**：跨阶段课程设计审计、多产物矛盾定位、多模块代码因果分析、来源冲突评估。选择当前可用的能力最强且适合该模态的模型。

若父 Agent 的模型已经符合任务档位，且切换模型不会带来明确收益，可以继承父模型。模型覆盖需要使用非完整历史上下文时，只传递完成子任务所需的最小原始材料、文件路径和规则，不用整段主会话填充子智能体上下文。

### 选择思考强度

| 强度档位 | 适用条件 |
| --- | --- |
| `none` / `minimal` | 仅做确定性摘取、分类或格式整理；不需要搜索、代码推理或冲突判断，并且所选模型支持该档位 |
| `low` | 范围明确的搜索、文件扫描、链接核对和局部静态检查 |
| `medium` | 默认档位；用于普通调研、草稿生成、一致性审计和代码诊断 |
| `high` | 多来源冲突、非局部依赖、跨产物推理或错误决定会造成较大返工 |
| `xhigh` / `max` / `ultra` | 仅用于最困难且边界明确的异步审计，或较低档位已经暴露无法解决的关键矛盾；不得作为默认值 |

只能选择目标模型明确支持的档位。目标档位不可用时，选最接近且不高于必要成本的支持值。高思考强度不自动代表更好；若问题来自任务边界含糊、证据缺失或停止条件不清，先修正任务提示，不靠提高强度补偿。

### 常见任务默认档位

| 任务 | 默认模型档位 | 默认思考强度 | 升档条件 |
| --- | --- | --- | --- |
| 路径、状态和交接信息提取 | 轻量 | `low` | 文件之间存在矛盾时升为标准 / `medium` |
| 单一主题官方资料定位 | 轻量或标准 | `low` | 来源冲突、版本迁移时升为标准 / `medium` |
| 多来源课程调研 | 标准 | `medium` | 需要重构长期路线时升为复杂 / `high` |
| 大纲—练习—手册一致性审计 | 标准 | `medium` | 跨阶段依赖或大量断链时升为复杂 / `high` |
| 独立 `E-*` 或手册主题草稿 | 标准 | `medium` | 多模块框架行为或复杂配置时升为复杂 / `high` |
| 学习者代码错误复现与归因 | 标准编码 | `medium` | 非局部、多模块或并发问题时升为复杂 / `high` |

## 调用与上下文规则

1. 给每个子智能体一个具体、封闭、可验证的目标，不使用“研究一下”“完善全部内容”等开放描述。
2. 提示中明确：必须读取的规则与文件、允许使用的知识编号、禁止触碰的范围、是否允许写文件、完成标准、返回格式和分支预算。
3. 显式设置子智能体模型或思考强度时，使用 `none` 或有限的最近轮次传递方式，不传递完整历史；在支持 `fork_turns` 的环境中将其设为 `"none"` 或正整数字符串。确实需要完整历史时，省略模型和思考强度覆盖并继承父 Agent 设置。
4. 默认由主 Agent 统一协调。除非主 Agent 明确授权且仍有两个以上独立分支，子智能体不得继续递归委派，避免失控和额外 token 消耗。
5. 默认先启用一到两个子智能体；只有第三个分支能覆盖明确且不重复的缺口时才增加，且不得超过运行环境可用并发槽位。
6. 多个子智能体不得并行编辑同一文件或同一答案目录。允许写入时，只分配互不重叠的文件或目录；共享练习文档与答案文件默认由主 Agent 重新读取最新内容后统一写入。
7. 主 Agent 在等待期间继续完成可独立推进的工作，不为等待子智能体而停止整个任务。
8. 子智能体返回时列出结论、证据位置、未确认项、实际副作用和建议下一步。涉及代码时带文件与行号，涉及网络来源时带原始链接。
9. 主 Agent 检查结果是否符合知识边界、用户授权和当前文件状态。未经复核的子智能体结论不得直接写成课程事实或掌握状态。

## 分支预算与编排

每个子任务在调用前设置足以约束搜索和输出的预算，不以消耗完预算为目标：

- 指定允许读取的路径或主题范围；外部调研优先限定来源等级、目标版本和最多候选来源数，默认每个主题保留三个以内最相关来源。
- 指定返回上限，例如最多五项关键发现、必要证据和未确认项；不要返回长篇课程正文或重复转述输入。
- 达到完成标准立即停止。发现与其它分支重复、对当前决策无增量或需要等待前置结果时，提前结束并报告原因。
- 预算不足时，先停止扩展性草稿和补充性搜索，保留当前决策所必需的原始事实核对与一致性审计。
- 不因输出不够丰富自动重试或升档。只有缺少的证据会改变教学决策时，才扩大范围、换模型或提高思考强度。

大型阶段准备按依赖顺序编排：

1. 并行完成互不重复的来源调研或现状盘点。
2. 主 Agent 根据证据确定阶段边界、知识编号、练习关系和文件职责。
3. 按互斥任务契约并行生成独立练习或知识手册草稿。
4. 主 Agent 复核并统一写入持久化事实源。
5. 写入完成后再启动独立一致性审计；不得让审计与尚未定稿的草稿并行并据此作最终判断。

## 失败与停止条件

- 子智能体发现需要用户决策、额外授权、共享文件冲突或目标资料缺失时，停止相应分支并把阻塞点交回主 Agent。
- 同一分支连续两次没有新增证据时停止重试，由主 Agent 调整范围、换模型档位或亲自处理。
- 子智能体结果互相冲突时，不用多数票决定；主 Agent 回到原始文件、官方来源或学习者实际输出来裁决。
- 已获得足够证据完成当前教学决策后停止继续搜索，不为了“更全面”扩大调研范围。
