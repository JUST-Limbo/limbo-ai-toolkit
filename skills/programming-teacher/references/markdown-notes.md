# 学生学习笔记

在创建、补充或整理学生学习笔记时读取。笔记保存在项目 `.learning/notes/`，资料目录与职责以 [课程产物规范](curriculum-artifacts.md#学习资料目录) 为准。

## 笔记的用途

学习笔记帮助学生回顾已经学习的知识、理解案例、复盘实践和整理疑问。AI 根据实际课件学习、课堂互动、学习者作答与查阅结果协助整理，尊重学生已有的表达和记录习惯。

可以保存已学要点、案例观察、文档查阅结论、真实错误及解决方法，以及学生自己表达的理解和待解决问题。新增授课的完整讲解与教学案例由 HTML 课件保存，教学进度与掌握证据维护在大纲，教师参考答案维护在练习资料；笔记通过链接关联这些材料，同时保留便于独立复习的解释、关键代码和结论。

已有笔记保留其正文和记录习惯，包括学生已采用的 AI 整理内容。迁移旧课程时按 [已有课程迁移](curriculum-artifacts.md#已有课程迁移) 完整保留笔记，再在明确授权的范围内整理内容。

笔记随课程逐步积累，首次学习可从空笔记开始。学生自己的观点、心得和错误以其实际表达或实践结果为依据；教师整理的解释与学生原话分清来源。

## 目录与命名

笔记文件可按已学主题命名，例如：

```text
.learning/notes/
|-- README.md
|-- 变量与类型.md
|-- 集合与迭代.md
|-- 函数与模块.md
`-- 错误排查.md
```

`README.md` 提供笔记索引和必要的版本说明。文件按实际已学主题创建，同一主题的追问与新认识补入对应文件。笔记较多时可用英文子目录按主题分组；内容较少时也可使用一个中文命名的笔记文件。

概念、API、执行过程和相关案例放在相邻位置，便于以后查找。结构以学生的阅读与检索需要为准，兼顾概念之间的先修关系和课堂形成的理解。

## 内容组织

按当前学习内容选取必要小节，可参考以下结构：

```markdown
# <学习主题>

相关课件：<lessons/ 中的课件文件与章节锚点>

## 已学要点
<概念、用途、机制与适用版本>

## 案例与观察
<实际讲过或做过的案例、关键代码、运行入口与结果>

## 理解与疑问
<学生实际表达的理解、提问及已确认的解答>

## 问题与解决
<实际遇到的错误、原因、排查依据与解决过程>

## 复习提示
<需要回忆的重点、对比关系或相关练习链接>

## 资料来源
<具体文档、版本与查阅结论>
```

根据已发生的学习活动增减小节，保留便于复习的结论与依据。课堂中的临时安排和掌握状态由大纲维护，笔记重点记录可供回顾的学习内容。

## 案例与实践记录

引用已学课件的案例章节，记录学生自己的解释、对比和观察；例如笔记可链接到 `../lessons/01-functions.html#predict-output`。完整讲解和教学案例的维护见 [HTML 课件规范](html-lessons.md#api-与框架案例)。

记录学生实践时，可保留关键代码、输入输出和排错过程，并链接到实际工程文件。教师参考答案通过 [练习资料](curriculum-artifacts.md#完整答案要求) 中的准确编号与文件位置提供。

代码块标明语言，区分预期输出和实际观察。尚未运行的内容标为“未在当前环境验证”，未解决的问题标明当前已知信息和待确认项。

工具操作记录用途、系统与版本、命令或点击路径、完成标志、实际失败与处理方式，以及是否需要重启。资料链接指向具体页面或章节，并关联 `.learning/resources.md` 中的对应来源。

## 维护节奏

1. **学习过程中**：记录实际完成的阅读、互动和观察所形成的理解与疑问，并关联课件位置；等待学生回答时，在大纲记录当前检查点和教学状态。
2. **完成一轮讲解或练习后**：依据真实反馈整理要点、案例、错误与查阅结论，归入相应主题。
3. **复习时**：结合新的理解补充或修正笔记，保留有价值的易错点与对比。
4. **写入前**：重新读取 Markdown 最新内容，保留学生自行编辑的文字；冲突时说明位置并确认处理。删除、移动或批量重命名已有笔记前确认范围。
5. **写入后**：按 [文档维护汇报](curriculum-artifacts.md#文档维护汇报) 定位变更，在课堂讲解和互动之后简短说明。
