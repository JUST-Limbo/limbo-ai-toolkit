# 学生学习笔记

整理实际学过的知识、代码案例与问题结论，形成可独立复习的笔记。

## 文档命名策略

笔记保存在 `.learning/notes/`，文件名采用“学习序号 + 课程、阶段或主题”，如 `01-java-basics.md`、`02-lombok.md`，也可使用中文。序号按首次建立顺序确定，后续补充沿用原文件；已有目录与命名遵循用户约定。

## 文档拆分策略

每门课或学习阶段维护一个主线文档，按需拆出专题：

- **主线文档**：保留核心知识、必要示例与知识衔接，支撑连贯复习。
- **专题文档**：承载独立、可复用或展开后打断主线的内容；短内容留在主线。

拆出专题后，主线保留必要概念、用途和链接，详细讲解与案例集中维护。优先补充已有文档，同一专题跨课程复用；拆分、移动或重命名时同步链接并保留必要上下文。

## 文档内容维护策略

### 维护口吻

采用知识总结、案例分析和问题复盘的客观口吻，将实践提炼为通用知识。交代概念、成立条件、关键示例与结论，使笔记可独立复习。

### 案例讲解

- 根据理解需要安排顺序：有具体问题时先展示代码与现象，需要先修概念时先补充必要知识。
- 用关键代码、命令和输入输出说明知识，交代必要数据、调用关系、结果与边界；错误案例说明原因和修正结果。
- 单行语句、变量或输出的简短解释写在代码注释中，流程与原理写在代码块外，避免重复。
- 复用示例时明确对应类、方法或章节及变化；独立示例说明其独立性，避免混淆变量与状态。

### 维护检查与汇报

依据实际学习反馈更新，写入前重读最新内容并保留用户编辑。代码标明语言、必要运行条件与结果，如实说明验证情况；仅在影响理解或运行时注明版本，安装、依赖与配置保留必要版本。

维护后检查概念、示例、运行条件与结论是否齐备，用 `已维护到XX文档XX节XX小节XX点` 汇报位置，附可点击文件路径。
