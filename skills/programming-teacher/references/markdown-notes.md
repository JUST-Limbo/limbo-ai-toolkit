# 学生学习笔记

整理实际学过的知识、代码案例与问题结论，形成可独立复习的笔记。

## 知识归档与命名

笔记保存在 `.learning/notes/`，按“一门课或一个学习阶段一个主线文档，按需配套多个专题文档”组织。已有笔记沿用用户确认的目录与组织方式，在本次维护范围内逐步补充。

- **主线文档**：承载本课程或阶段的核心知识、必要示例与知识之间的衔接，保持学习脉络连贯，正文能够支撑核心内容的复习。
- **专题文档**：承载可独立理解、适合跨课程复用的知识模块，或只需了解、展开后容易打断主线的次要内容。重要的独立模块也可以单独成文；内容较短时保留在主线，不为分层而拆文件。

主线在相关小节保留理解所需的概念、用途和专题链接，详细讲解与案例集中在专题文档中维护，避免两处重复。同一专题跨阶段、跨课程持续补充，新的主线链接已有专题。例如 Java 基础主线维护语法、面向对象与集合等核心内容，Lombok 等独立模块可另设专题，主线保留其用途及阅读入口。

文件名以学习顺序加课程、阶段或知识主题命名，例如 `01-java-basics.md`、`02-lombok.md`、`03-java-web.md`，也可使用中文。序号按文档首次建立的学习顺序确定，后续补充沿用原文件；正文按知识关系组织。维护前先判断内容归属，优先补充对应主线或已有专题；拆分、移动或重命名时同步相关链接，保留必要上下文。

## 维护口吻

采用知识总结、案例分析和问题复盘的客观表述，将项目中的实践提炼为通用知识。正文围绕当前知识点交代概念、成立条件、关键示例代码与结论，补充理解代码所需的数据和执行上下文，使读者直接依据笔记完成理解与复习。

## 案例与讲解顺序

根据知识特点与用户基础选择展开方式：有熟悉背景或具体问题时，先展示代码与现象，再解释原理；理解案例需要先修概念时，先说明必要知识，再给出示例。多个知识相互关联时，可交替使用短示例与局部解释，沿理解需要自然展开。

优先用关键示例代码、命令及必要输入输出展示知识，示例范围按当前知识点确定，交代必要的数据与调用关系。文字围绕用途、关键语句、运行结果和边界作简明解释；概念性内容用简洁定义与对比说明，实践错误用相关代码、原因与修正结果呈现。

针对单行语句、变量取值或输出结果的简短说明，直接以注释写在对应代码处；涉及多段代码、执行流程或底层原理的说明放在代码块外。同一说明不在注释和正文中重复。

示例复用已有代码时，明确指出对应的类、方法或章节，以及本次变化，避免含糊的“以上例为基础”。独立示例使用同名类或容易与前文混淆时，说明其独立性，不让读者误以为需要沿用前一示例的变量或状态。

## 维护与汇报

依据实际学习反馈补充或修正对应知识文件。写入前重新读取最新内容，保留已有正文与用户新增编辑；代码标明语言、必要运行前提及预期或实际结果，验证情况如实说明。版本差异影响语法、行为或运行条件时，在相关知识点简短注明必要条件，避免为普通示例重复标注学习环境版本；安装、依赖与项目配置保留必要的具体版本。

维护后检查概念说明、示例代码、运行条件与结论是否齐备，确认正文能够独立支撑复习，并用 `已维护到XX文档XX节XX小节XX点` 汇报具体位置，附可点击文件路径。
