# 学生学习笔记

整理实际学过的知识、代码案例与问题结论，形成可独立复习的笔记。

## 知识归档与命名

笔记保存在 `.learning/notes/`，以完整知识主题建立文件，例如 Redis、HTTP 或并发。同一主题跨阶段、跨课程持续补充，其下属知识点和案例通过文件内的章节组织；例如 Redis 的数据类型、持久化和缓存实践统一维护在 Redis 笔记中。

文件名以学习顺序加知识主题命名，例如 `01-redis.md`、`02-http.md`、`03-concurrency.md`，主题也可使用中文。序号按主题首次学习的先后确定，后续补充沿用原文件；文件名调整时同步已有引用。序号组织阅读顺序，正文按知识关系组织。

## 维护口吻

采用知识总结、案例分析和问题复盘的客观表述，将项目中的实践提炼为通用知识。正文围绕当前知识点交代概念、成立条件、关键示例代码与结论，补充理解代码所需的数据和执行上下文，使读者直接依据笔记完成理解与复习。

## 案例与讲解顺序

根据知识特点与用户基础选择展开方式：有熟悉背景或具体问题时，先展示代码与现象，再解释原理；理解案例需要先修概念时，先说明必要知识，再给出示例。多个知识相互关联时，可交替使用短示例与局部解释，沿理解需要自然展开。

优先用关键示例代码、命令及必要输入输出展示知识，示例范围按当前知识点确定，交代必要的数据与调用关系。文字围绕用途、关键语句、运行结果和边界作简明解释；概念性内容用简洁定义与对比说明，实践错误用相关代码、原因与修正结果呈现。

## 维护与汇报

依据实际学习反馈补充或修正对应知识文件。写入前重新读取最新内容，保留已有正文与用户新增编辑；代码标明语言、适用版本、必要运行前提及预期或实际结果，验证情况如实说明。

维护后检查概念说明、示例代码、运行条件与结论是否齐备，确认正文能够独立支撑复习，并用 `已维护到XX文档XX节XX小节XX点` 汇报具体位置，附可点击文件路径。
