# Markdown 笔记规范

## 文档命名策略

文件名采用“学习序号 + 课程、阶段或主题”，如 `01-java-basics.md`、`02-lombok.md`，文件名可使用中文。序号按首次建立顺序确定，后续补充沿用原文件；已有命名遵循用户约定。

## 文档拆分策略

- **主线文档**：每门课或学习阶段维护一个主线文档，保留核心知识、必要示例与知识衔接，支撑连贯复习。
- **专题文档**：承载独立、可复用或展开后打断主线的内容；短内容留在主线。
- **临时知识点**：暂时无法归入已有主题的零散内容，集中记录在 `临时知识点.md`；归属明确后迁入对应主线或专题，移除临时文档中的重复正文。
- **次要知识点**：归属明确但较少使用或只需了解的非重点内容，可留在对应主题，标题或句首标记「了解即可」或「次要」；也可单独拆出文档，拆出后在原主题保留必要链接。

## 文档内容维护策略

### 维护范围

- 写入前重读最新内容，保留用户编辑；用户限定某小节或某个知识点时，只改指定范围，不顺手改写或补全相邻正文。
- 不擅自添加学习安排、复习顺序、总结清单或“什么时候使用某技术”等扩展章节，不把对话中的知识串讲改成学习流程。

### 内容取舍

- 重点讲清常用、推荐写法，保留理解所需的示例、调用上下文和结果。
- 对不常用或非重点的知识，不过分扩展广度和深度，介绍核心概念即可，按需给出案例代码。
- 仅在影响理解或运行时简要注明版本差异；安装、依赖与项目配置保留必要版本。

### 维护口吻

直接陈述知识、原理和结论，使用客观的技术笔记口吻，不保留对话中的称呼、问答衔接和教学指令。

### 案例代码讲解

- 案例代码优先做到清晰、自解释；仅对核心逻辑和不易理解的关键点补充说明，避免逐行解读或重复代码已表达的信息。
- 单行语句、变量或输出的简短解释应直接写在代码注释中，不在案例外重复表述。

### 常用方法维护规范

+ 常用方法按静态方法、实例方法分表整理，常量按用户需要另列。

+ 方法表格包含「方法、作用、调用示例、返回结果」四列。示例使用具体参数，返回结果与该次调用对应。
