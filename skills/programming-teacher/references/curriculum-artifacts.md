# 教学产物与一致性规范

## 何时读取

在创建或维护学习路线、教学大纲、练习簿、阶段设计和知识手册时读取。准备向用户出题前，也要执行本文件的“一致性检查”。

## 三类持久化产物

默认只建立三类学习产物；现有项目有其它合理结构时先适配，不强行迁移。

| 产物 | 核心职责 | 应包含 | 不应包含 |
| --- | --- | --- | --- |
| 学习计划 / 教学大纲 | 作为 Agent 的持久化教学指令，决定学什么、如何教、顺序、掌握深度和如何验收 | 阶段目标、细化到概念与 API 的知识和工具单元、先修关系、教学顺序与策略、练习链接、状态、证据、复习安排 | 完整题干、完整答案、面向学习者的长篇知识正文 |
| 练习簿 | 承载大纲配套的完整实践设计；可由文档与答案代码目录共同组成 | 题目、知识引用、约束、提示、答案文档、实际代码文件、自检方式、解析 | 重复整份大纲、与大纲无关的临时题、与答案目录重复的整份源码 |
| 学习笔记 / 知识手册 | 为学习者提供稳定、完整、可检索的知识正文 | 用途、机制、时序、通用教学案例、易错点、排错、资料来源 | 课程进度、课堂聊天、下一轮安排、成套题目及其答案 |

课堂对话是教学媒介，不是唯一状态存储。学习者练习工程用于动手和按需验证；`answers/` 中的参考代码属于练习簿，但不要求成为可独立运行的工程。文件存在也不代表掌握。

可以用一个文件或目录表达一类产物，例如：

```text
学习目录/
|-- 学习计划.md
|-- 练习簿/
|   |-- README.md
|   |-- exercises/
|   |   `-- E-JAVA-LIST-03.md
|   `-- answers/
|       `-- E-JAVA-LIST-03/
|           `-- src/
`-- 知识手册/
    `-- <主题>.md
```

文件名和拆分方式服从现有项目约定，职责边界保持不变。

## 阶段设计必须落盘

开始阶段教学前，必须把阶段设计写入实际文件。至少包括：

- 阶段目标、先修条件和进入下一阶段的门槛
- 是否沿用、扩展或更换练习模型，以及理由
- 全部知识、API、语法、注解、框架行为和工具操作
- 每个知识或工具单元对应的说明/使用文档、具体章节、语言、适用版本和查阅任务
- 每个单元的掌握深度、教学顺序、呈现策略和纠偏重点
- 全部候选练习、提示阶梯、由文档和实际文件组成的完整答案、自检方式与验收标准，并标记必做、可选、合并或复验
- 阶段综合题、变式题和延迟复验安排
- 面向学习者的本阶段完整知识手册初稿

这些内容不得只留在 Agent 当前上下文。用户对练习时机的选择只改变候选题的启用状态和顺序，不临时生成脱离大纲的题目。后续发现遗漏时，先同步更新教学大纲、练习簿和知识手册，再继续教学或出题。每次写入后按下方「文档维护汇报」说明改动位置。

## 文档维护汇报

每次编辑教学大纲、练习簿、知识手册或其它学习文档后，立即按 `已维护到XX文档XX节XX小节XX点` 汇报：

- `XX文档` 使用文件名或可识别标题，可附绝对路径。
- 按实际标题层级定位到改动所在最深处；没有更深层时如实省略，不虚构层级。
- frontmatter、表格单元格或列表项使用最近标题，并以字段名、知识编号、练习编号或列表主题作为改动点。
- 一次修改多处时分别汇报，或在同一句中用分号逐项列出。
- 只报告路径或“已更新某文件”不够，学习者应当无需查看 diff 就能定位改动。

## 教学大纲的精度

大纲应细化到能检查是否超纲的最小有意义单元，而不是只列“大主题”。为单元分配稳定编号：

- `K-*`：语言、框架和工程知识
- `T-*`：环境、工具、IDE 和操作技能
- `E-*`：练习

编号形式可适配现有项目，但必须稳定且可双向引用。

知识单元至少记录：

```markdown
### K-SPRING-MVC-04：请求体绑定

- 内容：JSON 请求体到 Java 对象的转换
- 具体项：`@RequestBody`、Jackson 反序列化
- 先修：K-JAVA-OBJECT-03、K-HTTP-BODY-01
- 教学时机：新增 JSON 接口之前
- 掌握深度：理解并会用
- 核心：绑定发生在 Controller 方法执行前
- 允许查阅：注解的低频可选属性
- 暂不要求：Jackson 源码和自定义反序列化器
- 配套文档：[请求体说明](<具体官方文档 URL>)（官方中文优先，适用于 <版本>）
- 查阅任务：从文档中找到 `@RequestBody` 处理请求体的说明，并用一句话关联到当前案例
- 对应练习：E-SPRING-MVC-04
- 教学状态：未讲 / 已讲
- 掌握状态：未评估 / 学习中 / 待巩固 / 已掌握
- 掌握证据：<独立程度、提示级别和验证结果>
```

工具单元同样具体到实际操作：

```markdown
### T-MAVEN-02：重新加载依赖

- 具体操作：Maven Reload、查看依赖是否进入项目
- 教学时机：第一次修改 `pom.xml` 时
- 掌握深度：会用
- 是否背快捷键：否
- 配套文档：[依赖重新加载说明](<具体官方文档 URL>)（适用于 <版本>）
- 查阅任务：在文档或 IDE 帮助中找到重新加载入口，并确认完成标志
- 完成标志：依赖不标红，目标类可引用，项目可编译
- 对应练习：E-TOOL-MAVEN-01
```

计划进度、掌握证据和复习日期默认维护在教学大纲中，不另造一份与大纲脱节的状态表。

## 练习簿条目

每道练习必须包含完整答案，并与题目放在同一练习簿体系中。编码题由练习文档和 `answers/<E-*>/` 实际代码文件共同组成；操作题、口述题或无需独立文件的短答案可以直接写在文档中：

```markdown
## E-JAVA-LIST-03：条件筛选

### 对应教学大纲

- 教学单元：集合与业务筛选
- 必需知识：K-JAVA-LIST-02、K-JAVA-LIST-03、K-JAVA-IF-01
- 可选知识：无
- 暂不使用：Stream API、Lambda 表达式
- 目标深度：独立应用

### 题目

<完整说明任务场景、目标和必要背景，不粘贴答案实现>

### 题目契约

| 项目 | 内容 |
| --- | --- |
| 新建或修改文件 | <精确路径> |
| 公开方法或操作 | <名称与职责> |
| 入参 | <名称、类型与约束> |
| 返回值 | <类型与含义> |
| 成功行为 | <可观察结果> |
| 失败行为 | <各失败条件及对应结果> |
| 本题不做 | <明确边界，例如不改登录接口> |
| 自检方式 | <唯一一种且与题目形态一致的检查方法；只写 Service 就不要写 Postman 调接口> |

表格字段和顺序固定，内容不得为空；确实不适用时填写“无”并说明原因，不得用“见答案”“同上”“按现有实现”等模糊表述替代。「自检方式」行与下方同名小节描述同一种检查方法；下方小节只补充命令、输入和预期结果，不得增加第二种自检。

### 完成标准

- <功能结果>
- <边界条件>
- <代码约束>

### 自检方式

<命令、测试输入和预期结果；须与题目形态一致，且只写一种：只写 Service 就不要写 Postman 调接口>

### 分级提示

1. <定位提示>
2. <概念提示>
3. <伪代码或局部骨架；不得把题目契约藏进本级提示>

### 完整答案

- 答案形式：代码文件 / 文档正文
- 答案目录：`../answers/E-JAVA-LIST-03/`（编码题填写）
- 沿用基础：<无，或精确列出沿用的 E-* 与文件>
- 新增文件：<路径清单>
- 修改文件：<路径清单；答案目录中保存本题结束时的完整文件>
- 删除文件：<路径清单或无>

<操作题、口述题或短答案在此写完整步骤或结论；编码题不在此重复粘贴整份源码>

### 答案文件核对

- 答案目录与所列文件路径存在
- 新增、修改、删除清单与实际文件一致
- 沿用的 `E-*` 和来源文件可以精确定位

### 答案解析

- 关键步骤与职责
- 使用的知识编号
- 常见错误
- 其它合理实现的判定方式
```

文档答案可以用 `<details>` 折叠，代码答案可以放在明确命名的 `answers/` 目录中，以减少意外看到，但这些方式都不是访问控制。完整答案不得粘贴到教学对话或知识手册；需要查看时，应告知练习文档、练习编号、“完整答案”小节和答案目录，必要时提供对应链接。

题干契约不等于完整答案。新建或修改哪些文件、公开方法或操作、入参、返回值、成功行为、失败行为、本题不做，以及一种与题目形态一致的自检方式，必须按固定字段和顺序写在「题目契约」表中；对话布置习题时必须从该表读取并按主 Skill 的「开题契约」固定格式完整输出，任一项缺失都不得要求学习者开始编码。这不算泄露完整答案。禁止贴进对话的仍是答案方法体、完整源码、可直接粘贴编译通过的实现。分级提示的「伪代码或局部骨架」不得把契约自己藏起来。

## 完整答案要求

- 编码题在 `answers/<E-*>/` 中保存本题新增或修改后的完整文件；文档列出答案目录、沿用基础、新增、修改和删除文件。源码的权威副本是答案目录中的实际文件，不在 Markdown 中重复维护整份源码。
- **沿用项**只能精确指向练习簿中已有的 `E-*` 及其答案文件，例如「沿用 `E-3-1-04` 的 `answers/E-3-1-04/src/User.java`」。禁止用「见仓库」「同工程」「见知识手册」等模糊位置代替本题依赖。
- **静态完整判定**：练习文档、答案目录和所列沿用 `E-*` 应清楚表达本题结束时新增、修改或删除了什么。修改文件必须保存该步结束时的完整文件，不能只保存 diff、半截类或待填空骨架。
- 不用省略号、伪代码或“其余自行实现”替代答案文件中的关键部分。
- 覆盖题目全部功能、边界和约束。
- 只使用题目允许且大纲已经安排教学的知识。
- **拆步题**在自己的答案目录中保存本步改动后的完整文件，不要半截里程碑，也不要把后一节仓库终态提前写进本题必要答案。后一节知识可标为扩展，但不能成为本题验收偏好；终态实现放在该能力真正完成的那一题。
- 不要求为每题复制完整工程、补齐未改动文件或无关依赖，也不要求默认编译、运行、测试参考答案或维护答案运行验证状态。题目的自检方式服务于学习者判断完成情况，不等于 Agent 必须预先运行参考答案。自检必须与题目形态一致，且每题只写一种：只要求写 Service，就不要把自检写成 Postman 调接口。
- 配置、依赖、测试或数据文件只有在本题新增、修改或理解它们是完成题目的必要条件时，才进入答案目录和文件清单。
- 存在多种正确实现时，答案只是参考，不要求学习者逐字一致。
- 未来知识可以作为标明的扩展方案，但不能成为当前题目的必要答案或验收偏好。

修改题目、知识范围、文件名、依赖、输入输出、自检方式、验收标准，或工程 / 配置 / 知识手册中的可观察行为（接口、状态码、表结构、依赖等）后，必须同一轮同步修改对应 `E-*` 的答案文档、文件清单和实际代码文件，并重新执行静态一致性检查。

知识手册中的案例用于解释知识，练习簿中的答案用于完成特定题目。**练习文档与 `answers/` 实际文件共同构成权威练习簿**：题意、提示、路径和解析以文档为准，编码答案源码以实际文件为准。知识手册与答案代码完全相同时使用精确链接，不复制维护两份；不得把练习簿改成只链手册、学习者工程或其它未受练习簿管理的位置。

## 双向可追溯

大纲与练习簿是同一教学设计的两个视图，关系可以多对多：

- 每道练习的每个必需知识编号都必须在大纲中存在，且安排在练习之前或当前单元内讲解。
- 大纲中目标为 `会用`、`独立应用`、`排错与迁移` 的知识必须有练习验证；简单 API 可以合并进综合题，不要求一项一题。
- 题干、提示、答案文档、答案代码、自检方式和验收标准都受同一知识边界约束。
- 大纲中出现名字不等于已经讲过；向用户出题前还要检查其 `教学状态` 为 `已讲`。`掌握状态` 单独记录，不能用“已讲”冒充“已掌握”。
- 练习或答案需要新知识时，先更新大纲、教学顺序和知识手册，再补讲或推迟练习。

向用户出题前检查：

1. 所有必需知识是否有稳定编号并存在于大纲？
2. 是否已经实际讲解到足以完成该题的深度？
3. 题干是否出现未讲过的术语、API、注解、工具或隐式行为？
4. 提示和答案是否偷偷依赖后续知识？
5. 验收强度是否与声明的掌握深度一致？
6. 大纲中的核心知识是否能由本题或其它题验证？
7. 题目、答案文档、答案目录和文件清单是否同步？
8. 本题答案目录是否保存全部新增或修改后的完整文件，并如实记录删除项，而没有为了独立运行复制无关工程内容？
9. 沿用项是否精确指向已有 `E-*` 的答案文件，而不是笼统指向仓库、工作区或知识手册？
10. 本题必要答案是否夹带尚未讲授的后一节实现？
11. 不打开 `answers/<E-*>/`、只看题目、「题目契约」表、完成标准和自检方式，学习者能否独立下手？须逐行确认表中的新建或修改文件、公开方法或操作、入参、返回值、成功行为、失败行为、本题不做和自检方式均具体、非空且相互一致；自检方式还须与题目形态一致且只有一种。任一项缺失、使用模糊占位，或必须先打开答案目录或「完整答案」才能开工，则检查失败。有 `<details>` 或答案目录存在，不能代替本条。

检查失败时，先补练习文档、答案文件和教学，或修改、推迟练习；不能用临时口头解释绕过。答案目录存在不能代替第 7～10 条的静态一致性检查；有 `<details>` 或答案目录也不能代替第 11 条。

## 环境、工具和 IDE 产物要求

安装、构建工具、IDE 操作、调试、代码生成和快速输入都属于大纲知识。第一次真实需要前应登记并教学：

- 解决什么问题，为什么现在需要
- 当前操作系统和工具版本下的完整命令或点击路径
- 完成后观察什么
- 常见失败表现和排查入口
- 是否需要重启终端、IDE 或运行中的项目
- 掌握深度：独立操作、会用、仅需知道入口或允许查阅

重要操作在练习簿中设置操作题并在练习文档内写完整步骤、预期观察和解析，无需为纯操作或口述题创建 `answers/<E-*>/` 代码目录；纯快捷键或低频入口可并入真实任务，不强制单独出题或背诵。

知识手册保存稳定操作路径和排错方式；课堂只在当前步骤揭示需要的操作，避免开课时灌输工具大全。
