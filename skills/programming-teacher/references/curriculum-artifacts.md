# 课程与教学产物

在建立或维护路线、阶段、练习和产物索引时读取。本文件统一定义资料目录、产物职责、练习分层与参考答案管理。

## 学习资料目录

先确认实际学习项目根目录，结合目录规则、Git 和构建配置识别项目；教学材料以 `<project-root>/.learning/` 为统一根目录。学习者业务代码保存在项目正常源码目录，教师参考答案保存在 `.learning/exercises/answers/`。

```text
<project-root>/
|-- .learning/
|   |-- README.md
|   |-- curriculum/
|   |   `-- syllabus.md
|   |-- lessons/
|   |   `-- 01-functions.html
|   |-- assets/
|   |   `-- lessons.css
|   |-- exercises/
|   |   |-- README.md
|   |   |-- E-001-list-filter.md
|   |   `-- answers/
|   |       `-- E-001-list-filter/
|   |           `-- src/
|   |-- notes/
|   |   |-- README.md
|   |   `-- 集合与迭代.md
|   `-- resources.md
`-- src/
```

- `.learning/README.md`：学习动机、最终目标、技术基线、教学偏好和资料索引。
- `curriculum/syllabus.md`：教学大纲、当前进度、掌握证据和复习安排；篇幅较大时可将阶段设计拆到 `curriculum/stage-01-<topic>.md`，由大纲链接。
- `lessons/<sequence>-<topic>.html`：单元授课正文、案例、查阅任务和学习检查点；大纲与根索引提供课件入口。
- `assets/`：课件共享样式和实际需要的测验、图示或模拟组件；首次生成课件时建立 `lessons.css`，其它资源按复用需要创建。
- `exercises/README.md`：单元练习与综合项目的索引；每题一个 `E-001-<topic>.md`，按需准备的参考源码位于 `exercises/answers/E-001-<topic>/`。课堂小练习直接放在会话或课件中；目录按实际需要创建。
- `notes/README.md` 与主题文件：学生学习笔记的索引、已学知识、案例、疑问和实际反馈。
- `resources.md`：可信来源、适用版本、访问日期及采用理由，格式见 [source-policy.md](source-policy.md#记录来源)。

生成的目录名采用英文。`notes/` 内的学习笔记正文与文件名可以使用中文，例如 `集合与迭代.md`；其它资料文件名采用英文，普通英文文件名使用 kebab-case。`README.md`、`K-*` / `T-*` / `E-*` 标识沿用约定。代码答案中的类名、文件名和包结构遵循目标语言与工程规范，目录按实际产物创建。

恢复已有课程时按现有文件定位进度。升级 Skill 涉及旧路径或材料形态调整时，按 [已有课程迁移](#已有课程迁移) 保全资料并更新入口。

## 产物职责

| 资料 | 服务对象 | 保存内容 |
| --- | --- | --- |
| 教学大纲 | AI 老师 | 目标、先修、知识与工具单元、教学顺序、深度、练习映射、状态、证据和复习安排 |
| HTML 课件 | 学习者与 AI 老师 | 完整教学正文、案例、来源、学习检查点及关联练习入口 |
| 练习资料 | AI 老师与学习者 | 任务与完成标准，以及按需提供的提示、自检、行为约定和参考答案 |
| 学生学习笔记 | 学习者 | 已学概念、课堂案例、查阅结论、真实疑问、错因与复习摘要 |

大纲中的 `K-*` / `T-*` 链接到课件文件与章节锚点、已有笔记和相关 `E-*`；单元练习与综合项目关联主要知识单元，课堂小练习可沿用课件检查点。学习位置与教学证据由大纲维护，笔记链接随学习补充。课件生成规范见 [html-lessons.md](html-lessons.md)。

同一主题可以同时有课件讲解和学生笔记。权威位置按资料职责确定：课件维护授课正文，笔记维护学习记录；通过链接关联，保留各自的阅读价值。

## 已有课程迁移

迁移用于调整资料位置和授课方式，同时保全已有内容、学习记录与引用关系。按以下顺序处理：

1. **盘点与范围**：读取目录规则、当前文件和链接，列出原路径、目标路径、资料职责及处理方式。Skill 更新与课程资料迁移分别说明；用户已明确授权的范围直接执行，需要扩大的范围再确认。
2. **保全已有笔记**：默认将学习笔记完整迁入 `.learning/notes/`，保留正文、章节结构、代码、来源和学习记录，仅按迁移需要调整路径与链接。学生已采用的 AI 整理内容也属于已有笔记。旧文档混合知识讲解与个人记录、或内容来源难以区分时，先整体保留；可以从中提取通用讲解生成 HTML，并关联原笔记。
3. **明确内容整理范围**：迁移到 HTML 与 `.learning/` 的授权覆盖授课方式和目录调整。将已有笔记摘要化、改成课件索引、删减正文或重新拆分，需要用户明确认可具体处理范围；可先展示受影响章节和整理方案，等待答复期间继续完成保留原文的迁移与课件准备。已有明确授权时按该范围处理。
4. **核对后切换入口**：对照迁移前材料逐节核对正文、代码块、来源与学习记录，检查本地链接和锚点；记录保留、提取及获准精简的去向。迁移与生成课件沿用原有教学状态、掌握证据和练习编号。确认目标资料完整且入口更新后，在已授权范围内移除旧路径副本。
5. **修复已有迁移**：核对当前内容与迁移前可恢复版本，优先使用包含最后编辑内容的原文件或备份，必要时从 Git 历史补回缺失正文。将当前新增记录合入恢复后的笔记，保留已生成且有效的课件；无法恢复或有内容冲突的部分列明并交由用户确认。

写入前重新读取目标 Markdown，保留期间新增的编辑。迁移汇报说明路径映射、内容保全结果、明确获准的删减及待处理项；涉及笔记时同时遵循 [笔记维护规范](markdown-notes.md)。

## 阶段与单元准备

新阶段开课前把设计保存到大纲或关联阶段文件，包括：

- 能力目标、先修条件、阶段门槛、预计投入和补强路径。
- 练习模型的沿用、扩展或更换方式，以及选择理由。
- 具体知识、API、语法、注解、框架行为与工具操作；登记教学顺序、目标深度、呈现策略和纠偏重点。
- 配套文档的具体章节、语言、版本与查阅任务。
- 候选练习的目标、复杂度及必做、可选、合并、复验安排；当前要布置的题目按 [练习资料](#练习资料) 准备。
- 练习关联的主要知识、HTML 课件中的案例与检查点；复杂题按需核对容易遗漏的前提。
- 本阶段课件安排、综合题、变式题和延迟复习安排；学生笔记按实际学习逐步整理。

已规划阶段中的后续单元，核对并补齐本次目标、先修、对应课件和关联练习即可。阶段范围或顺序变化时更新阶段设计。当前单元完整课件在开始学习前就绪；练习开题前明确任务与完成标准，参考答案按需准备。课堂小练习可根据即时反馈出题，后续题只需先规划目标。

## 教学大纲

用“最小有意义的能力单元”细化大纲，为知识、工具与练习分配稳定编号：

| 标识 | 用途 |
| --- | --- |
| `K-*` | 语言、框架和工程知识 |
| `T-*` | 环境、工具、IDE 和操作技能 |
| `E-*` | 需要独立保存的单元练习与综合项目 |

每个单元记录内容与具体项、先修、教学时机、目标深度、核心与允许查阅项、范围边界、文档与查阅任务、课件位置、学习检查点进度、已有笔记链接、对应练习、教学状态、掌握状态、证据和复习安排。工具单元还记录具体操作、版本前提和完成标志。例如：

```markdown
### K-SPRING-MVC-04：请求体绑定

- 内容：JSON 请求体转换为 Java 对象
- 具体项：`@RequestBody`、Jackson 反序列化
- 先修：K-JAVA-OBJECT-03、K-HTTP-BODY-01
- 教学时机：新增 JSON 接口之前
- 目标深度：理解并会用
- 核心：绑定发生在 Controller 方法执行前
- 允许查阅：注解的低频可选属性
- 范围边界：本单元聚焦默认绑定机制
- 配套文档与查阅任务：<具体页面、版本、待定位信息>
- 课件位置：<lessons/ 中的 HTML 文件与章节锚点>
- 学习检查点：<已完成项、待完成项与下一阅读位置>
- 学习笔记：<notes/ 中的已有笔记链接；尚未整理时标明待整理>
- 对应练习：E-004-request-body
- 教学状态：未讲 / 讲解中 / 已讲
- 掌握状态：未评估 / 学习中 / 待巩固 / 已掌握
- 证据与复习安排：<实际表现、提示级别、验证结果与复习时机>
- 后续教学调整（按需）：<影响下一步的学习发现、实际依据与调整建议>
```

教学状态和掌握证据的判定以 [课堂工作流](learning-workflow.md#教学状态与掌握证据) 为准。按范围汇总进度时，汇总状态由各单元的实际证据共同支持。

## 练习所需知识

根据任务核对核心知识是否已经讲解、学习者是否有相应基础，以及允许查阅哪些内容。发现未教的必要知识时，先补讲或缩小题目范围；允许查阅的内容给出可用入口。

多文件、框架隐式行为或复杂依赖容易遗漏前提时，可从已有参考实现反查必要知识，重点检查首次出现的 API、配置、工具和失败分支。用简短清单记录实际缺口即可；逐文件知识映射表和完整参考实现都是按需工具，不作为普通练习的开题前提。

## 练习资料

按学习任务的复杂度选择材料。三层用于决定准备范围，不要求课堂向学习者宣告分类，也不按代码行数机械划分。

| 类型 | 适用情况 | 材料要求 |
| --- | --- | --- |
| 课堂小练习 | 预测输出、口述解释、文档定位、局部改写或短编码 | 在会话或课件中明确任务与预期；无需独立文件、`E-*` 编号、完整答案或契约 |
| 单元编码练习 | 独立实现一个方法、类或单元功能，需要后续反馈与复习 | 保存题目、完成标准和必要提示，关联主要知识单元；输入输出、自检方式与参考答案按需补充 |
| 综合项目 | 跨模块、多个步骤或存在工程依赖的连贯任务 | 明确文件范围、行为边界、已有工程前提与分步验收；复杂时再准备详细契约或完整参考实现 |

例如：循环输出预测可直接在会话作答；列表筛选方法可保存题目、样例和完成标准；订单接口项目按可运行步骤列出本步文件、成功与失败行为及验证方法。

单元练习与综合项目保存到 `.learning/exercises/E-001-<topic>.md` 并加入索引。以“任务”和“完成标准”为核心，按需要添加背景、主要知识、输入输出、约束、提示、自检或答案小节。已有材料可沿用，补齐本次真正缺少的信息即可。

### 开题说明与自检

开始练习前，直接给出题目或指向准确的课件章节、练习文件，让学习者知道要做什么、从哪里开始、怎样算完成。简单题用短段落或列表即可。

涉及多人可能理解不同的接口行为、跨文件职责或复杂边界时，可用“题目契约”集中说明文件路径、方法、入参、返回值、成功与失败行为、范围和验证方式。只写实际需要约定的项，字段数量、顺序和表现形式由题目决定。

自检选择与题目匹配的现有方式，例如解释理由、对照预期输出、运行方法、测试或调用接口。提供命令或操作时写清入口、输入和预期结果；所依赖的环境与入口应已可用，或属于本题明确要完成的步骤。只写 Service 的题目优先直接检查 Service 行为，无需额外建设接口。自检方法的数量按实际需要选择。

### 参考答案

参考答案用于讲评、对照或澄清复杂实现，按教学需要提前准备、在反馈后补充或在学习者要求时提供；普通练习开题不以完整答案就绪为前提。

- 课堂小练习可直接在会话或课件中给出结论、理由或短代码。
- 单元练习可在题目文档中用 `<details>` 保存思路、关键代码与简短解析；需要独立源码时放到 `.learning/exercises/answers/<exercise-id>/`。
- 综合项目按需保存参考实现。提供完整实现时，文件与必要依赖应完整，说明运行前提、沿用位置和本步改动；拆步答案对应本步结束状态。
- 明确区分思路、局部示例与完整实现；答案覆盖声明的完成标准，接受满足要求的其它正确实现。提示和参考实现使用已学知识，额外方法标为扩展。
- 查看答案时提供已有材料的准确位置。默认核对内容与路径；需要实际结果支撑判断，或学习者要求运行验证时，再执行相应检查。

独立保存的答案由练习资料维护，课件与笔记通过链接引用。教学案例使用与单元练习或综合项目相同的知识结构以及不同的业务名和数据，帮助迁移应用。

## 出题前检查

开题前简要确认三件事：任务匹配已学知识与当前目标；学习者有足够信息开始；完成标准清楚且能据此反馈。小练习随课堂直接确认，单元练习和综合项目额外检查实际涉及的工程前提、边界与验证方式。

发现缺口时补充说明、补讲或调整题目。修改练习时，只更新实际受影响的题干、完成标准、已有答案或引用；改变目标与进度时更新大纲，课件引用题目时更新展示内容，笔记依据真实学习反馈补充。已有完整材料继续保留，无需为采用分层设计重新整理所有旧题。

## 文档维护汇报

编辑学习资料后，用 `已维护到XX文档XX节XX小节XX点` 说明准确位置。文件名或标题可附绝对路径；按实际最深标题定位，表格与列表用字段、知识编号、练习编号或主题标识改动点。多处修改可逐项或用分号汇报。

课堂中的维护汇报放在本轮讲解与互动之后，保持简短。跨会话需要保存交接说明时使用 `curriculum/handoff.md`，其内容由 [课堂工作流](learning-workflow.md#复习与跨会话交接) 定义。
