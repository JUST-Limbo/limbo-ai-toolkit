# 课程与教学产物

在建立或维护路线、阶段、练习和产物索引时读取。本文件统一定义资料目录、产物职责、练习契约、答案管理与出题检查。

## 学习资料目录

先确认实际学习项目根目录，结合目录规则、Git 和构建配置识别项目；教学材料以 `<project-root>/.learning/` 为统一根目录。学习者业务代码保存在项目正常源码目录，教师参考答案保存在 `.learning/exercises/answers/`。

```text
<project-root>/
|-- .learning/
|   |-- README.md
|   |-- curriculum/
|   |   `-- syllabus.md
|   |-- lessons/
|   |   `-- 01-functions.html
|   |-- assets/
|   |   `-- lessons.css
|   |-- exercises/
|   |   |-- README.md
|   |   |-- E-001-list-filter.md
|   |   `-- answers/
|   |       `-- E-001-list-filter/
|   |           `-- src/
|   |-- notes/
|   |   |-- README.md
|   |   `-- 集合与迭代.md
|   `-- resources.md
`-- src/
```

- `.learning/README.md`：学习动机、最终目标、技术基线、教学偏好和资料索引。
- `curriculum/syllabus.md`：教学大纲、当前进度、掌握证据和复习安排；篇幅较大时可将阶段设计拆到 `curriculum/stage-01-<topic>.md`，由大纲链接。
- `lessons/<sequence>-<topic>.html`：单元授课正文、案例、查阅任务和学习检查点；大纲与根索引提供课件入口。
- `assets/`：课件共享样式和实际需要的测验、图示或模拟组件；首次生成课件时建立 `lessons.css`，其它资源按复用需要创建。
- `exercises/README.md`：练习索引；每题一个 `E-001-<topic>.md`，对应参考源码位于 `exercises/answers/E-001-<topic>/`。
- `notes/README.md` 与主题文件：学生学习笔记的索引、已学知识、案例、疑问和实际反馈。
- `resources.md`：可信来源、适用版本、访问日期及采用理由，格式见 [source-policy.md](source-policy.md#记录来源)。

生成的目录名采用英文。`notes/` 内的学习笔记正文与文件名可以使用中文，例如 `集合与迭代.md`；其它资料文件名采用英文，普通英文文件名使用 kebab-case。`README.md`、`K-*` / `T-*` / `E-*` 标识沿用约定。代码答案中的类名、文件名和包结构遵循目标语言与工程规范，目录按实际产物创建。

恢复已有课程时，先盘点文件和链接。材料位于旧路径时，列出迁入 `.learning/` 的路径映射，确认迁移范围后迁入并更新索引、交接信息与交叉引用，使每份材料有一个权威位置；并发编辑的文件在写入前重读，内容冲突交由用户确认。

## 产物职责

| 资料 | 服务对象 | 保存内容 |
| --- | --- | --- |
| 教学大纲 | AI 老师 | 目标、先修、知识与工具单元、教学顺序、深度、练习映射、状态、证据和复习安排 |
| HTML 课件 | 学习者与 AI 老师 | 完整教学正文、案例、来源、学习检查点及关联练习入口 |
| 练习资料 | AI 老师与学习者 | 题目、契约、提示、自检、验收、参考答案和解析 |
| 学生学习笔记 | 学习者 | 已学概念、课堂案例、查阅结论、真实疑问、错因与复习摘要 |

大纲中的 `K-*` / `T-*` 链接到课件文件与章节锚点、已有笔记和相关 `E-*`；练习反向声明所需知识。学习位置与教学证据由大纲维护，笔记链接随学习补充。课件生成规范见 [html-lessons.md](html-lessons.md)。

## 阶段与单元准备

新阶段开课前把设计保存到大纲或关联阶段文件，包括：

- 能力目标、先修条件、阶段门槛、预计投入和补强路径。
- 练习模型的沿用、扩展或更换方式，以及选择理由。
- 具体知识、API、语法、注解、框架行为与工具操作；登记教学顺序、目标深度、呈现策略和纠偏重点。
- 配套文档的具体章节、语言、版本与查阅任务。
- 候选练习及必做、可选、合并、复验安排；计划中的编码题预先准备题目、提示、完整答案、自检和验收。
- 练习与知识的映射、HTML 课件中的案例与检查点，以及从编码答案反查的必要知识。
- 本阶段课件安排、综合题、变式题和延迟复习安排；学生笔记按实际学习逐步整理。

已规划阶段中的后续单元，核对并补齐本次目标、先修、对应课件和关联练习即可。阶段范围或顺序变化时更新阶段设计。当前单元完整课件在开始学习前就绪；计划布置编码题时，题目与答案材料在开题前就绪。非编码练习按操作、口述或观察任务的实际形式准备。

## 教学大纲

用“最小有意义的能力单元”细化大纲，为知识、工具与练习分配稳定编号：

| 标识 | 用途 |
| --- | --- |
| `K-*` | 语言、框架和工程知识 |
| `T-*` | 环境、工具、IDE 和操作技能 |
| `E-*` | 正式练习 |

每个单元记录内容与具体项、先修、教学时机、目标深度、核心与允许查阅项、范围边界、文档与查阅任务、课件位置、学习检查点进度、已有笔记链接、对应练习、教学状态、掌握状态、证据和复习安排。工具单元还记录具体操作、版本前提和完成标志。例如：

```markdown
### K-SPRING-MVC-04：请求体绑定

- 内容：JSON 请求体转换为 Java 对象
- 具体项：`@RequestBody`、Jackson 反序列化
- 先修：K-JAVA-OBJECT-03、K-HTTP-BODY-01
- 教学时机：新增 JSON 接口之前
- 目标深度：理解并会用
- 核心：绑定发生在 Controller 方法执行前
- 允许查阅：注解的低频可选属性
- 范围边界：本单元聚焦默认绑定机制
- 配套文档与查阅任务：<具体页面、版本、待定位信息>
- 课件位置：<lessons/ 中的 HTML 文件与章节锚点>
- 学习检查点：<已完成项、待完成项与下一阅读位置>
- 学习笔记：<notes/ 中的已有笔记链接；尚未整理时标明待整理>
- 对应练习：E-004-request-body
- 教学状态：未讲 / 讲解中 / 已讲
- 掌握状态：未评估 / 学习中 / 待巩固 / 已掌握
- 证据与复习安排：<实际表现、提示级别、验证结果与复习时机>
- 后续教学调整（按需）：<影响下一步的学习发现、实际依据与调整建议>
```

教学状态和掌握证据的判定以 [课堂工作流](learning-workflow.md#教学状态与掌握证据) 为准。按范围汇总进度时，汇总状态由各单元的实际证据共同支持。

## 从答案反查必要知识

准备、布置或恢复编码练习时，读取练习文档和实际答案文件，逐文件提取必要知识：

- 类型、构造方式、方法、返回类型与调用顺序。
- 语法、注解、泛型、匿名类、类型转换和异常处理。
- 依赖、配置、命令和工具操作。
- 框架自动创建、注入、绑定、序列化或拦截等隐式行为。
- 失败分支、输入输出和数据形态。

在练习文档中维护映射：

| 必要知识 | 答案位置 | K/T 编号 | 目标深度 | 课件案例 | 教学证据 |
| --- | --- | --- | --- | --- | --- |
| <API、语法或行为> | <文件与方法> | <具体编号> | <深度> | <课件文件与章节锚点> | <实际状态与依据> |

已有可靠证据的基础知识可以合并记录；首次出现、版本敏感、框架隐式或易阻塞编码的项目单列到准确的知识单元。目标为 `会用` 及以上的项目在课件中提供完整案例，练习前完成对应学习活动与理解检查。发现缺口时补大纲和课件，再引导学习者完成前置学习。

## 练习资料

正式练习先保存到 `.learning/exercises/E-001-<topic>.md`，包括：

1. **对应大纲**：教学单元、必需和可选知识、范围边界、目标深度。
2. **题目**：任务场景、目标、必要背景；编码题附下方固定题目契约。
3. **完成标准**：功能、边界和代码约束。
4. **自检方式**：一种匹配题目形态的检查方法，写清已有入口、完整命令或操作、输入、预期结果。
5. **分级提示**：定位 → 概念 → 伪代码或局部骨架。
6. **完整答案**：编码题给出 `answers/E-001-<topic>/` 相对链接、精确沿用来源、新增/修改/删除清单；操作或口述题保存完整步骤或结论。
7. **答案解析**：关键职责、知识应用、常见错误和其它合理实现的判定方式。

题目、契约和自检共同提供独立开工所需的信息。答案文档可用 `<details>` 折叠，答案代码保存在明确命名的目录中，供学习者主动查看。

### 编码题契约与课堂输出

编码题文档用 `### 题目契约` 保存以下固定表；布置该题时读取此表，以“开题契约”为标题在课件或会话中完整展示，然后再邀请学习者开始编码。采用课件展示时，会话指向准确的课件章节锚点和练习编号。HTML 与 Markdown 保持相同字段、顺序和表格结构：

```markdown
### 开题契约

| 项目 | 内容 |
| --- | --- |
| 新建或修改文件 | <学习者工程中的精确路径> |
| 公开方法或操作 | <名称与职责> |
| 入参 | <名称、类型与约束> |
| 返回值 | <类型与含义> |
| 成功行为 | <可观察结果> |
| 失败行为 | <各失败条件及对应结果> |
| 范围边界 | <本题职责与限制> |
| 自检方式 | <唯一一种、已可执行且与题目形态一致的方法> |
```

每个字段填入具体内容；不适用的字段写“无”并说明原因。自检小节仅补充同一种方法的命令、输入与预期结果。只写 Service 的题目，应使用能直接观察 Service 行为的检查入口；需要调用接口时，接口必须属于本题已有的工程前提。入口、脚本、测试或数据在开题时可用，题目契约在题干中直接可见。

### 完整答案要求

编码题的权威源码位于 `.learning/exercises/answers/<exercise-id>/`，遵循以下规则：

- 保存本题新增或修改后的完整文件，覆盖约定功能、边界和失败行为；文档如实列出删除项。
- 沿用内容精确指向已有 `E-*` 的答案文件，例如 `answers/E-001-list-filter/src/Item.java`。
- 拆步题保存本步结束时的完整文件，按教学顺序逐步扩展；后续实现放在对应后续题中。
- 文件清单覆盖本题必要的代码、配置、依赖与数据；未改动工程基础通过精确引用沿用。
- 提示与必要答案均处于本题已安排教学的知识边界；其它实现作为明确标注的扩展。
- 教师参考答案默认检查静态完整性、文件清单和路径一致性。需要实际结果支撑当前判断，或用户要求运行验证时，再执行相应检查。

每题的答案可依赖既有工程基础。自检服务于学习者判断完成情况，参考答案的准备范围由题目决定。接受符合契约的其它正确实现。

完整答案只保存在练习资料体系；课件、会话与学习笔记通过准确的练习编号、答案小节和文件链接引导查看。教学案例保存在 HTML 课件中，使用与练习相同的知识结构以及不同的业务名和数据。题意与解析以练习文档为准，源码以答案文件为准。

## 出题前检查

编码题开题前逐项核对：

1. **知识与教学**：题干、提示、答案、工具和隐式行为全部映射到具体知识单元；课件有完整案例，各必需项已完成目标深度的学习活动与理解检查，证据可定位到每项。
2. **题目与目标**：难度、验收强度和声明深度一致；目标为 `会用` 及以上的知识有本题或其它练习验证。
3. **契约与自检**：固定字段具体、完整、一致，唯一自检入口已可用；只看题目、契约和完成标准即可独立下手。
4. **答案与文件**：实际文件、清单、新增/修改/删除和沿用链接一致，每步文件完整并符合当前知识范围。
5. **知识反查**：逐文件读取答案，核对反向知识清单、教学证据和课件案例，尤其检查首次出现或易阻塞知识。

缺项时先补课件、补教或调整练习安排，再开题。题目、知识范围、路径、依赖、自检、验收或工程可观察行为改变时，同一轮同步受影响的大纲、练习文档、答案文件、HTML 课件和已有笔记，重新检查一致性。

## 文档维护汇报

编辑学习资料后，用 `已维护到XX文档XX节XX小节XX点` 说明准确位置。文件名或标题可附绝对路径；按实际最深标题定位，表格与列表用字段、知识编号、练习编号或主题标识改动点。多处修改可逐项或用分号汇报。

课堂中的维护汇报放在本轮讲解与互动之后，保持简短。跨会话需要保存交接说明时使用 `curriculum/handoff.md`，其内容由 [课堂工作流](learning-workflow.md#复习与跨会话交接) 定义。
