# HTML 课件生成与维护

在规划大纲、生成、维护或预览教材时读取。大纲与详细课件统一保存在课程根目录的 `.learning/lessons/`；学生笔记按 [笔记规范](markdown-notes.md) 维护，阶段项目见 [课堂工作流](learning-workflow.md#阶段项目)。

## 大纲与教材层级

按 [课程调研](source-policy.md#调研课程路线) 考察公开项目、文章目录、B 站选集及专栏，将采用结构组织为“阶段 → 单元 → 具体知识点”。总览说明课程目标、阶段顺序、先修与成果；阶段页展开具体概念、语法、API、框架行为和工具操作，标明目标深度、阶段项目及教材位置。

大纲节点、教材与笔记的标题、目录和文件名均可使用中文，按知识主题清楚命名；英文名称采用 kebab-case。教材正文页以学习顺序加主题命名，例如 `01-类型.html`、`02-函数.html`、`03-集合.html`，阶段内按教学顺序编号。总览与阶段目录保留 `index.html` 作为固定入口；文件名调整时同步目录与已有引用。例如“请求体绑定”可展开为 JSON 数据形态、`@RequestBody`、反序列化时机、对象字段匹配和失败输入，实际范围通过来源与课程目标核实。

教材完备表达大纲：每个必需知识点都有可定位的讲解和附答案的理解检查，目标为“会用”及以上时提供完整示例。核对先修顺序、知识覆盖和阶段成果的能力闭环，待编写内容显示明确材料状态，已完成链接指向真实页面与锚点。

## 从课程目标生成课件

读取当前单元的目标、先修、掌握深度、知识范围与可信资料。代码案例和必要实操明确所属 [阶段项目](learning-workflow.md#阶段项目)，从教学任务确定课件必须解释的知识及工程前提。

总览页 `lessons/index.html` 承载完整大纲，阶段页 `lessons/<stage>/index.html` 展开单元与具体知识点，教材页按连贯主题组织正文，例如 `lessons/stage-01-basics/01-types.html`。每个必需知识点从目录链接到真实章节锚点，教材页提供返回阶段、总览及相邻单元的导航；页面数量按内容规模确定。

按总览与阶段页的知识点逐节编写教材，完成状态由正文、示例和检查点的实际覆盖支持。新阶段说明教学目标、先修、阶段项目、关键知识与查阅入口；后续单元补齐当前目标所需内容。知识点的教学安排见 [讲解与练习的难度](learning-workflow.md#讲解与练习的难度)。

课件按主题组织以下内容：

- **导读**：本单元目标、先修、适用版本、掌握深度与允许查阅项。
- **知识讲解**：问题、概念、机制、执行时序和必要语法。
- **完整案例**：准备条件、代码、输入、输出、失败行为与观察方式。
- **学习检查点**：以问答题组织预测、解释、代码追踪或文档定位，必要时增加局部代码实操，注明预期动作和反馈方式。
- **问答与实践解析**：每题的参考答案或判断依据、关键理由和代码解释，统一使用默认收起的折叠块。
- **资料与项目入口**：具体官方页面、查阅目的、所属阶段项目与前后单元链接。
- **小结与复习**：概念关系、关键对比和适合主动回忆的问题。

完整教学正文随教材保存，学习者可独立理解概念、示例和结论。学习检查点使用稳定锚点，例如 `#理解检查`，供目录及课堂导读定位；检查点提示先作答再对照答案，需要讨论时回报理由或结果。

## 教材正文表述

以教材方式说明概念定义、成立条件、机制、操作步骤、示例和结论。每节自行交代必需背景，章节间引用使用具体标题与链接，代码标明所属阶段项目、文件位置和运行前提，表达采用客观、明确、可复读的句子。

课堂补充先提炼为稳定知识，再写入对应章节。例如“异常沿调用栈向外传播，直到匹配的捕获分支处理”为机制说明；“对象字段缺失时的默认行为”可作为独立小节标题。教材中的操作提示说明读者要完成的动作和观察结果。

## API 与框架案例

目标为 `会用` 及以上的 API、语法或框架能力，课件覆盖：

1. 解决什么问题，以及当前任务为何需要。
2. 目标版本的依赖或 import，以及对象来自构造、工厂、注入还是自动配置。
3. 最小输入、完整调用、返回类型、输出或状态变化。
4. 必需局部语法，包括泛型、匿名类、Lambda、类型转换或注解属性。
5. 异常、失败输入、关键边界和运行、调试或观察方法。
6. 用于理解检查的预测、解释、改写或查阅任务。

案例沿用已学工程骨架时，给出所属阶段项目、准确文件位置和运行入口；框架上下文较多时提供最小完整类或方法与调用方式。框架隐式行为讲清谁在何时完成动作、依赖哪些条件、缺失时如何表现，以及如何观察。教学案例可作为问答与必要实操的基础，需要验证迁移时再改变业务条件或数据。

## 问答实操与答案

小单元以课件问答为主，临时实操根据用户实际困难增加；大单元结束后的综合代码练习按训练价值安排，课堂选择方式见 [问答与必要代码实践](learning-workflow.md#问答与必要代码实践)。题目与任务直接保存在对应教材章节，简单任务说明动作与预期，综合任务说明工程前提和完成标准。

题目、完成标准、答案和解析直接保存在教材章节中。每个理解检查点先呈现问题与“请先作答，再展开参考答案对照”，随后使用以下结构，初始状态为收起，点击摘要可展开或收起：

```html
<section id="check-topic">
  <h3>理解检查</h3>
  <p>问题：说明示例中的关键行为及其原因。</p>
  <p>请先作答，再展开参考答案对照。</p>
  <details>
    <summary>展开参考答案</summary>
    <p>参考答案或判断依据：写出结论、成立条件和关键理由。</p>
  </details>
</section>
```

问答题给出结论与解释；开放题给出判断标准、必要要点及合理答案范围；代码任务给出当前步骤所需实现与关键说明。每个检查点单独配齐答案或判断依据，课堂通过稳定锚点定位题目。代码答案说明所属阶段项目、文件位置、依赖和运行前提；局部示例标明范围，拆步答案对应当前步骤。答案使用已学知识，额外方法标为扩展，接受满足完成标准的其它正确实现。

综合代码任务按需要明确文件范围、前提、成功与失败行为和运行验证方式，材料规模按任务需要确定。题目变化时同步实际受影响的答案与解析；目标变化更新总览或阶段页，用户实践形成的理解与错因补入笔记。

## 来源

按 [来源策略](source-policy.md) 核对事实，在相关讲解附近提供具体页面或章节链接，优先选择准确、适配目标版本的官方中文文档及可信中文文章、专栏和视频。必要的外文资料附中文说明与阅读范围；来源的版本、访问日期和采用理由统一记录在 `.learning/resources.md`。

## 共享课件资源

新课件以已确认的 [HTML 模板](../assets/lesson-example.html) 和 [配套样式](../assets/lesson-example.css) 为基础，复用紧凑排版、顶部固定目录、代码块、表格与折叠答案。替换示例中的课程信息、教学正文、目录项与锚点；总览和阶段页沿用相同样式，按课程结构组织内容，教材页补齐总览、阶段与相邻单元链接。

生成课件前查看 `.learning/assets/`，复用已有样式、测验、图示或模拟组件。第一份课件将模板样式保存为 `.learning/assets/lessons.css`，按教材位置调整 HTML 的样式引用，后续课件统一引用；新增组件有明确复用价值时放入 `assets/`，保持课件阅读风格和交互一致。

共享资源采用相对链接并支持本地直接打开，复杂交互按教学需要增加。分享或迁移课件时携带其本地资源依赖，并核对链接。

按页面所在层级计算资源路径：总览 `lessons/index.html` 使用 `../assets/lessons.css`，阶段内的目录与教材页使用 `../../assets/lessons.css`。教材集群内的跨页导航按实际文件位置计算相对路径。

## 可阅读、可打开的 HTML

- 每份 HTML 保存本课完整内容，采用 UTF-8、响应式布局和本地共享资源，可直接打开阅读；必要交互使用轻量脚本。
- 整体采用紧凑、朴素的教材布局，合理控制留白、段落间距和标题层级，颜色与组件服务于阅读、代码展示和理解检查。
- 用语义清楚的标题、段落、列表和导航组织正文，保证字号、对比度与代码可读性；宽代码块可横向滚动，打印时保留完整教学内容。
- 稳定锚点连接课件内的案例与检查点，本地文件使用相对链接。正文中的代码正确转义，代码块注明语言与运行位置。
- 测验或观察组件在操作后给出清楚反馈；选项采用相近的信息量与呈现形式，判断依据来自知识内容。开放题附评价依据并引导学习者回报回答，课堂反馈依据用户实际作答与观察结果。
- 课件和本 Skill 生成的共享资源在文件注释中记录 `programming-teacher` 与当前版本，便于后续对照维护。

### 视口顶部或底部目录

每份课件 HTML 提供本课目录，所有屏幕尺寸均固定显示在视口顶部或底部，HTTP 预览与本地直接打开时均可使用：

- 目录使用 `position: fixed` 保持可见，正文预留对应空间，标题设置滚动偏移，保证阅读与锚点定位时正文清楚可见。
- 目录按正文顺序列出主要章节（`h2`）与必要的小节（`h3`），用缩进表达层级，覆盖案例、学习检查点、练习入口和小结。前后课件链接作为独立导航保留。
- 使用带明确标签的语义化导航（如 `<nav aria-label="本课目录">`）和原生锚点链接，目标使用唯一、稳定的 `id`。点击目录跳到对应标题，支持键盘操作、地址栏锚点与刷新后定位；有固定页头时设置滚动偏移，使目标标题保持可见。
- 目录明确标示当前阅读章节；使用脚本跟随正文滚动更新时，同步 `aria-current="location"`，脚本不可用时仍能通过原生链接跳转。
- 各类屏幕均直接展示目录，窄屏采用紧凑换行或目录内横向滚动；长目录限制高度并在内部滚动，给正文保留充足阅读空间。打印时隐藏固定导航，让正文占满可打印宽度。
- 目录布局和样式复用 `assets/lessons.css`，确需脚本时复用本地共享脚本。新增、删除或调整章节时同步目录，已有引用的锚点保持稳定。

维护后通过静态检查核对知识覆盖、HTML 结构、资源路径、页面链接与锚点，以及正文、代码和逐题答案是否齐备；检查折叠答案采用原生 `<details>` 且省略 `open` 属性。完成后提供文件链接和章节位置，按 [教材维护与汇报](#教材维护与汇报) 汇报；页面效果由用户打开查看。

## 本地 HTTP 预览与自动刷新

课件默认可直接打开阅读。用户需要 HTTP 预览或自动刷新时，复用或启动本地服务并提供地址，由用户打开查看。

### 选择和启动服务

先确认课程根目录、本机运行时和已有预览命令。已有可用服务时核对其根目录、实际端口和目标课件，确认覆盖本课程资料后复用；已有适用的预览脚本时优先使用。需要新服务且终端工具可用时由 Agent 启动，保留进程或会话标识供后续检查和停止。

服务根目录应覆盖课件及本地依赖。默认布局以 `.learning/` 为根目录：`lessons/` 与 `assets/` 是同级目录，仅服务 `.learning/lessons/` 会导致 `../assets/` 资源无法访问。采用其它布局时按实际依赖确定最小必要根目录。

没有现成预览工具、且本机已有 Node.js/npm 时，可在课程根目录使用以下示例（端口可调整）：

```powershell
npx live-server .learning --host=127.0.0.1 --port=5500 --no-browser
```

首次执行 `npx` 可能下载依赖；已有本地安装时优先调用已有版本，临时预览采用临时运行方式。按实际环境处理下载权限或失败。此工具在 HTML、JS 保存后自动刷新页面，CSS 保存后可直接更新样式；预览刷新行为与参数见 [live-server 官方说明](https://github.com/tapio/live-server#usage-from-command-line)。

只有 Python 或暂时无法使用自动刷新工具时，可在课程根目录启动静态服务：

```powershell
python -m http.server 5500 --bind 127.0.0.1 --directory .learning
```

使用本机实际可用的 Python 3 命令，Windows 上可能为 `py`。此方案需保存后手动刷新页面；参数见 [Python 官方说明](https://docs.python.org/3/library/http.server.html#command-line-interface)。

新服务绑定 `127.0.0.1`。复用前核实已有服务的归属、服务根目录和响应；端口被其它进程占用时选用空闲端口，记录实际启动地址。预览期间保持服务运行，停止时仅结束当前任务启动的服务，并告知链接已失效。

### 预览交付

启动服务后确认日志和目标教材的 HTTP 响应，提供准确页面与章节地址供用户打开。手动刷新方案提醒保存后刷新页面。

交付时给出实际 HTTP 预览链接、文件链接和当前章节，说明是否自动刷新及服务是否仍在运行。运行会话或进程标识用于当前会话管理，新会话重新确认服务状态与目标页面响应。

服务启动受限时提供文件链接、适配本机的启动命令及静态检查结果。交付说明对应实际完成的检查。

## 持续保存课堂内容

授课中的稳定补充、关键新案例、来源修正和澄清回填到课件对应章节；用户的理解与实践经历按 [学习笔记规范](markdown-notes.md) 整理为正文完整的知识笔记。课堂导读通过章节链接定位教材。

课程目标、版本、知识范围或案例改变时，更新受影响的总览、阶段目录及教材正文；问题变化时同步其答案或判断依据。锚点调整时同步已有引用，接管课程按 [课堂工作流](learning-workflow.md#恢复课程与准备课堂) 判断学习位置与知识缺口。

## 教材维护与汇报

写入前重新读取目标文件最新内容，保留用户期间新增的编辑。新增与更新的正文采用本文件的教材表述，改动同步到实际受影响的目录、答案及引用。

每次维护后，用 `已维护到XX文档XX节XX小节XX点` 汇报，附可点击文件路径，按实际最深标题及题目或知识主题定位改动。

整份教材按工作开始时的大纲或原教材大节逐节推进。每完成一个原大节，核对知识覆盖、代码、问答答案及导航后，即时提示 `XX教材XX大节已完成` 并附位置；结尾汇总已完成范围与待完成项。新教材沿用已确定的大节，已有教材沿用维护前的大节边界。
