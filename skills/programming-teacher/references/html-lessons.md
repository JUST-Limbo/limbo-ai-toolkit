# HTML 教材规范

## 大纲与页面组织

依据 [课程调研](source-policy.md#调研策略) 和学习目标，按「章 → 节 → 知识点」组织教材：

| 页面 | 职责 | 路径示例（相对教材目录） |
| --- | --- | --- |
| 总览 | 课程目标、章节目录、先修与成果 | `index.md` |
| 章节目录（按需） | 小节、知识点、掌握深度与教材入口 | `basics/index.md` |
| 教材正文 | 按连贯主题讲解知识，提供案例与问答 | `basics/01-variables.md` |

标题和文件名可使用中文，英文名称采用 kebab-case；正文页按章节顺序编号，篇幅较少时可直接放在教材目录下。教材覆盖大纲中的必需知识点，未编写内容注明待编写，已完成条目链接到真实页面或章节。

## 教材内容与表述

- 正文包含目标与先修、知识讲解、教学案例、课件问答及相关资料，按主题安排，不机械套用固定章节。
- 只需了解的知识点，在对应标题后标记「（了解即可）」，如 `反射（了解即可）`；目录中的标题同步保留该标记。
- 采用客观的教材口吻，交代必要背景，使概念、案例与结论可独立理解。代码优先自解释，只讲核心逻辑与难点，避免逐行复述。
- 目标为「会用」及以上时提供完整示例，注明所属项目或独立示例范围、必要依赖、运行前提与结果。
- 仅在影响理解或运行时简要注明版本差异；安装、依赖与配置保留必要版本。
- 引用外部资料时，在相关讲解附近提供具体页面或章节链接。

## API 与框架案例

目标为「会用」及以上时，案例说明：

- **用途与前提**：解决什么问题，所需依赖、import，以及对象来自构造、工厂、注入还是自动配置。
- **调用与结果**：具体输入、完整调用、返回值或状态变化，以及理解案例必需的局部语法；依赖工程上下文时给出文件位置与运行入口。
- **机制与边界**：关键执行时序、异常与失败条件及观察方式。框架隐式行为说明由谁、何时完成，依赖什么条件。

## 课件问答与答案

围绕用途、输出预测、执行顺序和关键原理设置问答，题目与解析保存在对应教材章节。每题附结论和理由；开放题提供判断标准与合理答案范围。问题使用稳定锚点供目录和课堂定位。

## 模板使用

- 新建教材时，将 [工程模板](../assets/textbook-template/package.json) 的 `package.json`、`package-lock.json`、`.gitignore`、`.vitepress/` 源文件和 Markdown 示例复制到教材目录；排除 `node_modules/`、`.vitepress/cache/`、`.vitepress/dist/`。依赖安装在课程教材工程中。
- 在 `.vitepress/course.ts` 修改课程名称、简介与章节顺序，替换示例正文；后续新增 Markdown 并同步该目录配置。工程模板基于公开开源项目 VitePress。
- 问答使用模板注册的 `<Answer>` 组件，样式与交互由主题维护；图片放在 `public/` 或正文附近。已有工程保留其主题与配置，不重复初始化。
- 新增或修改的主题、组件在注释中记录 `programming-teacher` 与当前版本。

初始化只执行一次。日常写作修改对应 Markdown 和必要的导航配置，不重新复制模板、安装依赖或调整主题；依赖缺失或确需变更时再处理。

## 本地 HTTP 预览与自动刷新

使用本机 Node.js/npm，在教材工程目录执行。首次运行安装锁定依赖：

```powershell
npm ci
npm run dev
```

开发服务支持保存后刷新，正文修改优先复用已有服务。首次初始化、主题或配置变更及交付站点时验证构建；需要检查构建产物时再启动预览：

```powershell
npm run build
npm run preview
```

复用服务前核实教材目录、端口和目标页面，新服务仅绑定 `127.0.0.1`，提供实际预览地址。保留进程或会话标识，仅停止本任务启动的服务。工程通过 HTTP 阅读，不直接双击构建产物；分享部署时使用 `.vitepress/dist/`。
