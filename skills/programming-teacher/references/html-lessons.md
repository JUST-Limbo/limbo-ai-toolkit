# HTML 课件生成与维护

在生成、更新、检查或打开授课课件时读取。课件是可跨会话阅读的主要授课材料，保存在项目 `.learning/lessons/`；会话中的学习组织和状态判断见 [课堂工作流](learning-workflow.md)。

课件的单元组织、导航、来源引用和共享资源复用参考公开开源项目 [mattpocock/skills 的 teach](https://github.com/mattpocock/skills/blob/main/skills/productivity/teach/SKILL.md)。本仓库将这些做法接入已有的课程大纲、编码练习与学习证据流程。

## 从课程目标生成课件

读取当前单元的目标、先修、掌握深度、知识范围与可信资料。关联编码练习时，先按 [答案知识反查](curriculum-artifacts.md#从答案反查必要知识) 核对实际答案，再确定课件必须解释的知识。

每份课件围绕一个紧凑、可完成的学习目标，采用英文序号文件名，例如 `01-functions.html`；单元内容较多时可拆为连续课件，在大纲中关联文件与具体章节锚点。依照 [讲解与练习的难度](learning-workflow.md#讲解与练习的难度) 安排内容，以最小完整案例建立理解，再逐步展开必需概念。

课件按主题组织以下内容：

- **导读**：本单元目标、先修、适用版本、掌握深度与允许查阅项。
- **知识讲解**：问题、概念、机制、执行时序和必要语法。
- **完整案例**：准备条件、代码、输入、输出、失败行为与观察方式。
- **学习检查点**：预测、解释、局部改写、文档定位或小型观察任务，注明预期动作和反馈方式。
- **资料与练习入口**：具体官方页面、查阅目的、关联练习与前后单元链接。
- **小结与复习**：概念关系、关键对比和适合主动回忆的问题。

完整教学正文随课件保存，学习者可在没有前一轮聊天记录的情况下读懂。学习检查点使用稳定锚点，例如 `#predict-output`，供会话导读、大纲进度和笔记引用。提供前后课件及相关材料导航，并在检查点提示学习者向 AI 提问或回报结果。

## API 与框架案例

目标为 `会用` 及以上的 API、语法或框架能力，课件覆盖：

1. 解决什么问题，以及当前任务为何需要。
2. 目标版本的依赖或 import，以及对象来自构造、工厂、注入还是自动配置。
3. 最小输入、完整调用、返回类型、输出或状态变化。
4. 必需局部语法，包括泛型、匿名类、Lambda、类型转换或注解属性。
5. 异常、失败输入、关键边界和运行、调试或观察方法。
6. 用于理解检查的预测、解释、改写或查阅任务。

案例沿用已学工程骨架时，给出准确位置和运行入口；框架上下文较多时提供最小完整类或方法与调用方式。框架隐式行为讲清谁在何时完成动作、依赖哪些条件、缺失时如何表现，以及如何观察。教学案例使用与当前练习不同的业务名和数据，便于学习者迁移知识。

## 关联练习与来源

题目、契约、验收和答案以 [练习资料](curriculum-artifacts.md#练习资料) 为权威来源。课件可以引用或展示当前题目的题干与契约，并链接到具体 `E-*`；展示内容从练习文档提取，源题变化时同步更新。完整参考答案通过练习资料中的准确位置提供。

按 [来源策略](source-policy.md) 核对事实，在相关讲解附近提供具体页面或章节链接。每份课件推荐一项直接相关的一手资料，注明阅读目的与范围；来源的版本、访问日期和采用理由统一记录在 `.learning/resources.md`。

## 共享课件资源

生成课件前查看 `.learning/assets/`，复用已有样式、测验、图示或模拟组件。第一份课件建立共享样式 `assets/lessons.css`，后续课件统一引用；新增组件有明确复用价值时放入 `assets/`，保持课件阅读风格和交互一致。

共享资源采用相对链接并支持本地直接打开，复杂交互按教学需要增加。分享或迁移课件时携带其本地资源依赖，并核对链接。

## 可阅读、可打开的 HTML

- 每份 HTML 保存本课完整内容，采用 UTF-8、响应式布局和本地共享资源，可直接打开阅读；必要交互使用轻量脚本。
- 用语义清楚的标题、段落、列表和导航组织正文，保证字号、对比度与代码可读性；宽代码块可横向滚动，打印时保留完整教学内容。
- 稳定锚点连接课件内的案例与检查点，本地文件使用相对链接。正文中的代码正确转义，代码块注明语言与运行位置。
- 测验或观察组件在操作后给出清楚反馈；选项采用相近的信息量与呈现形式，避免格式暗示答案。需要 AI 判断的开放题，引导学习者把回答或结果发回会话；浏览器中的即时结果由学习者回报或工具观察后再作为证据记录。
- 课件和本 Skill 生成的共享资源在文件注释中记录 `programming-teacher` 与当前版本，便于后续对照维护。

### 侧栏目录

每份课件 HTML 必须提供本课侧栏目录，HTTP 预览与本地直接打开时均可使用：

- 桌面采用左侧目录、右侧正文布局；目录随页面滚动保持可见（如 `position: sticky`），过长时可独立纵向滚动，不遮挡正文。
- 目录按正文顺序列出主要章节（`h2`）与必要的小节（`h3`），用缩进表达层级，覆盖案例、学习检查点、练习入口和小结。前后课件链接作为独立导航保留。
- 使用带明确标签的语义化导航（如 `<nav aria-label="本课目录">`）和原生锚点链接，目标使用唯一、稳定的 `id`。点击目录跳到对应标题，支持键盘操作、地址栏锚点与刷新后定位；有固定页头时设置滚动偏移，避免标题被遮挡。
- 目录明确标示当前阅读章节；使用脚本跟随正文滚动更新时，同步 `aria-current="location"`，脚本不可用时仍能通过原生链接跳转。
- 窄屏将目录改为可展开、收起的导航（可用原生 `<details>`），保留全部目录项，不挤压正文或造成整页横向滚动；打印时隐藏侧栏并让正文占满可打印宽度。
- 目录布局和样式复用 `assets/lessons.css`，确需脚本时复用本地共享脚本。新增、删除或调整章节时同步目录；已被大纲或笔记引用的锚点保持稳定。

生成后核对内容与大纲、练习的一致性，检查本地链接、锚点、代码显示和交互。可用浏览器时按下方流程通过 HTTP 预览正文、窄屏布局与实际交互，检查侧栏目录的章节覆盖、跳转位置、当前章节标示、长目录滚动与窄屏展开收起；未能预览时说明已做的静态检查和未确认项。交付时提供可用预览地址、准确文件链接及本轮章节位置。

## 本地 HTTP 预览与自动刷新

浏览器工具预览课件时优先使用本地 HTTP 地址。HTML 仍保留相对资源链接和直接打开阅读的能力；遇到 `file://` 访问被拒绝时转用本地服务，避免反复重试同一被拒绝的地址。HTTP 服务解决协议与资源加载问题，浏览器工具是否允许访问本机地址仍以实际工具权限为准。

### 选择和启动服务

先确认项目根目录、本机运行时和已有预览命令。已有可用服务时核对其根目录、实际端口和目标课件，确认属于当前项目后复用；已有项目预览脚本时优先使用。需要新服务且终端工具可用时由 Agent 启动，保留进程或会话标识供后续检查和停止。

服务根目录应覆盖课件及本地依赖。默认布局以 `.learning/` 为根目录：`lessons/` 与 `assets/` 是同级目录，仅服务 `.learning/lessons/` 会导致 `../assets/` 资源无法访问。采用其它布局时按实际依赖确定最小必要根目录。

没有现成预览工具、且本机已有 Node.js/npm 时，可在项目根目录使用以下示例（端口可调整）：

```powershell
npx live-server .learning --host=127.0.0.1 --port=5500 --no-browser
```

首次执行 `npx` 可能下载依赖；已有本地安装时优先调用已有版本。按实际执行环境处理下载权限或失败，不为一次预览默认全局安装或修改项目依赖。此工具在 HTML、JS 保存后自动刷新页面，CSS 保存后可直接更新样式；这是预览刷新，不是应用状态保留式 HMR。行为与参数见 [live-server 官方说明](https://github.com/tapio/live-server#usage-from-command-line)。

只有 Python 或暂时无法使用自动刷新工具时，可在项目根目录启动静态服务：

```powershell
python -m http.server 5500 --bind 127.0.0.1 --directory .learning
```

使用本机实际可用的 Python 3 命令，Windows 上可能为 `py`。此方案需保存后手动刷新页面；参数见 [Python 官方说明](https://docs.python.org/3/library/http.server.html#command-line-interface)。

新服务绑定 `127.0.0.1`。端口被其它进程占用时换一个可用端口，记录实际启动地址；不要把已有监听当作本项目服务或停止无关进程。终端进程保持运行才能继续预览，避免启动后立即清理服务。停止时只结束本轮启动的服务，并告知预览链接已失效。

### 打开、检查和交付

启动后先确认日志和目标课件的 HTTP 响应，再让可用浏览器工具打开具体页面，例如 `http://127.0.0.1:5500/lessons/01-functions.html#predict-output`；不要把目录列表当成课件交付。检查共享 CSS、JS、图片、导航和章节锚点是否正常加载，再核对正文和交互。保存课件或共享资源后确认预览更新；手动刷新方案明确提醒刷新。

交付时给出实际 HTTP 预览链接、文件链接和当前章节，说明是否自动刷新及服务是否仍在运行。将可复用启动命令、服务根目录和地址格式简要写入 `.learning/README.md`；运行会话或进程标识仅用于当前会话管理，不作为跨会话仍可用的证明。新会话重新确认服务状态。

若浏览器仍拒绝本地 HTTP 访问，记录实际拒绝原因，提供地址供学习者在允许的浏览器中打开；若无法启动服务，提供文件链接、适配本机的启动命令与静态检查结果。明确哪些视觉与交互检查尚未完成，不因 HTTP 返回成功便声称浏览器预览已通过。

## 持续保存课堂内容

授课中的稳定补充、关键新案例、来源修正和澄清回填到课件对应章节；学习者自己的理解、疑问和实践经历由 [学习笔记](markdown-notes.md) 保存。完整课件正文通过章节链接引用。

大纲目标、版本、知识范围、教学案例或关联练习改变时，更新受影响的课件内容、来源与链接。修改锚点时同步大纲、笔记和交接中的引用。恢复旧课程时，以已保存课件和证据为准，缺失的必要讲解先补入课件，再组织学习。

从旧课程资料生成课件时，按 [已有课程迁移](curriculum-artifacts.md#已有课程迁移) 提取通用讲解并保全原笔记。课件交付与笔记保全分别核对，课件内容完整只证明授课材料已保存。
